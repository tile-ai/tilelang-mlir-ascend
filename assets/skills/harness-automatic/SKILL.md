# Harness Automatic

这是当前宿主内的自动运行模式，不是定时任务或脱离会话的后台服务。用户调用后直接开始；不要每完成一个节点就再次询问是否继续。沿用已确定的目标、各侧环境和权限，自动模式不扩大它们。

## 建立或恢复控制记录

读取 STATE、需求/决定、当前候选/结果、环境、账本和已有 AUTOMATIC。使用 [控制模板](assets/templates/automatic.md) 在 `.workspace/AUTOMATIC.md` 保存本次范围、协调者、状态、控制额度和步进日志，STATE 只链接它。没有明确目标或存在多任务歧义时只问必要选择，不默认把整个 ROADMAP 都做完。

已有控制记录先按 [模式切换与接管](../harness-resume/references/next-action.md#6-模式切换与接管) 核实归属和最新用户决定，不另开竞争循环。更换协调者须确认旧协调者退出；仍活跃的节点继续等待，不重新派发。替换节点执行者才须确认该节点不再写入。unknown job 保留身份与额度，不能重投。

用户明确给出的步数/停止条件优先；没有给出且现有记录也没有本轮额度时，采用 **最多 8 个控制步骤**，开始时说明并记录，不为这个可调整默认值额外审批。一步是一次有界节点工作或接收/恢复/问询动作，包含其收尾；启动前占用一个步骤，失败和中断仍计数，重连不清零。设备时间、仿真资源与试验次数继续由各自约定/账本限制，这个默认值不提供任何设备额度。

新控制批次可归档上一份记录；若仅是重连或继续同一批次则沿用已用步数。达到上限后不再开始新步骤并报告；已占步骤的在途动作、已有结果接收与原 job 必要恢复属于原步骤收尾，可在原权限/资源上限内完成，不重复占步，不借收尾新开实验。后续用户明确要求继续时，可建立关联上一批次的有限新批次，但不能自动续期。

占步与派发不能只在返回后记账：派发前保存步骤号、run、派发意图和可关联的请求标识，收到响应后补实际 agent ID。恢复先核对这条意图及宿主实际状态；响应丢失且无法确认是否已派发时保持 blocked，不再次派发。明确尚未派发时可完成原已占步骤的启动，不重新扣步。用户暂停/撤权仍优先，不因已经占步就必须启动。

## 循环

每步遵循 [统一下一步规则](../harness-resume/references/next-action.md)：

1. 读取最新用户决定、在途状态和结果，核对目标是否已满足及是否仍有必须收尾的事项。目标满足就交付，不能因为还有步骤就扩大工作。
2. 选择一个下一步，记录原因、输入身份、完成条件和本次步骤号。无可执行动作、需要真实回答或预算不足时按下节停止。
3. 按 [harness-resume](../harness-resume/SKILL.md) 生成/复用 TASK，预留该环境的资源。默认串行派发一个全新、无父会话历史的节点子 agent，只传项目根和 TASK 路径；主 agent 保持协调与接收职责，子 agent 不递归启动 automatic。没有子 agent 工具时记录 `execution_strategy: inline`，由当前 agent 按相同契约顺序执行，不强迫用户开新会话，也不假装已隔离上下文。
4. 保存实际 agent/run/job 身份。等待节点时持续处理其问题和用户新指令，先落盘切换请求再等待；停止请求须传给活跃节点。按环境约定有界查询/回收，工具等待采用短的有界调用。不要提交后即宣称任务已完成或保证会话结束后后台继续。
5. 检查交付、身份、精度/性能/采集判定、作业与预算，接收后更新 STATE、EXPERIMENTS、环境或候选及控制日志。只有必要证据满足任务验收才更新最佳候选和目标达成状态。
6. 比较本步前后：有新候选、有效证据、已解除缺口或明确的新失败线索才继续推进相应路线。相同输入/环境/动作已失败且没有新依据时停止，不通过换 agent、改 run ID 或重写摘要掩盖无进展。未达性能目标但有新假设且预算允许时可继续优化。

主 agent 不在“已派发”或“准备执行”的中间状态结束本轮并声称 automatic 完成；应等待/收尾到完成、明确等待用户、预算边界或可恢复的阻塞。宿主打断时保留当前记录，下一次先恢复原作业。

## 停止、问询与恢复

- `completed`：当前目标有必需证据支持，交付已汇总，必需收尾已完成。不是某个子 agent 单独 completed。
- `needs_input`：有影响下一动作的真实未知选择；将问题 ID/影响范围落盘并向用户提问，未收到回答不猜。收到有效回答且未要求停止时可继续本批次原额度；范围改变先更新任务。
- `budget_exhausted`：达到控制步数或必需资源额度，不开始新步骤/实验。交付已有结果与差距，不自动加额；已占步骤的结果接收、记录与有权限的原作业恢复按原步骤收尾，unknown 额度不释放。
- `blocked`：工具/资源故障、未确认作业、结果身份冲突，或相同条件下无进展。写具体原因、原作业与解除条件；不要求用户重新回答已确定环境。
- `paused`：用户明确要求暂停、停止或转成单步；停止新增派发，保存在途任务。停止协调不等于外部作业已取消，不自动重置设备或清理未决资源。

status 查询只读，不改变循环。用户请求 next 时，先持久化单步请求及绑定的当前动作，到完成或等待/阻塞边界后保持连续模式 paused；不能等到收尾才保存切换。后续回答节点问题不会自行恢复 automatic。各方向切换、跨入口归属与计数遵循共用模式切换规则。

结束时回报控制状态、已用/上限、完成的节点与证据、当前/最佳候选、未测和在途事项、停止原因与推荐下一步。上下文压力较大时先保存检查点并建议新会话；用户继续当前会话也可接续，不以换会话为执行前置。
