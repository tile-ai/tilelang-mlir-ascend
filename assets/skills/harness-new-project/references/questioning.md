# 连续追问与收敛

两个初始化入口共用本指南。目标是帮助用户把想法讲清楚，使后续研究、需求和阶段规划有依据。

## 从用户的叙述开始

先复用会话、项目记录和已读文档中的决定。没有背景时，让用户描述想做什么、眼下哪里不顺，先听完整体想法；已有背景时，从其中最值得展开的线索开始，不重新问“你想做什么”。不要一开始就用 shape、工具链、部署方式等技术选项限制想法。

## 每轮根据上一答推进

1. 从用户刚才的回答中选一条重要线索：反复强调的痛点、含糊的目标、影响范围的取舍，或与已有证据冲突的说法。
2. 用一个具体追问深入这条线索。通常一轮一个主题；紧密相关的问题可以合问，但没有“总共问三题就结束”的上限或必须问满的配额。
3. 等待真实回答，吸收用户的修正，再决定下一问。异步提问尚未收到回答时，可以做无依赖的只读研究，不能替用户选答案，也不能推进依赖该答案的定稿。
4. 区分用户决定、已有事实与 agent 建议。发现假设就点明；尚未解决的关键歧义继续追问。

追问方式按当前线索选择：

| 用户表达 | 有效的下一问 | 要澄清的内容 |
| --- | --- | --- |
| “现在的调优流程太麻烦” | “最近一次调优，哪一步最耗你的时间？” | 动机与具体痛点 |
| “这个算子要快” | “你最想改善哪个实际调用场景？现在主要慢在哪里？” | 使用情境；明确后再问基线与测量范围 |
| “需要动态 shape” | “一次编译要覆盖哪些输入变化？能给两个实际调用的例子吗？” | 动态语义，而非直接假定每个 shape 重编译 |
| “精度和参考一样” | “这里的一样是逐位一致，还是允许误差？参考中哪些行为必须保留？” | 可观察的验收和兼容边界 |
| “先把已有项目接进来” | “接入之后你最先希望继续哪项工作？” | 未来目标，避免仅把当前实现抄成需求 |

这些是启发追问的示例，按当前线索选择，不作为必问题库。

## 选项与自由表达

有两三种具体理解或取舍时，使用宿主可用的提问工具给出短选项，说明差别。选项应来自当前对话，例如“单次编译支持范围内输入”与“按 shape 分别编译”；不要只给“技术 / 业务”一类抽象分类，不用推荐选项暗中代替用户决定。

用户说“我来讲一下”“不是这些情况”或希望展开描述时，停止连续弹选择题，改用普通文本邀请其讲述，并等待输入。吸收完自由表达后，确实需要比较具体方案时再恢复选项。文本问题放在宿主允许的对话位置；没有提问工具时直接用文本，不虚构工具或命令。

## 在后台检查理解是否充分

逐轮检查自己能否清楚说明：要做什么、为什么做、给谁或在哪个实际场景使用、怎样算完成。算子任务再结合 [项目记录](project-records.md) 中的需求维度查漏。清单只辅助判断下一问，不决定对话顺序。

onboard 还需分清“现有实现是什么”和“用户希望接下来怎样”，不能用源码自动填补用户意图。能从文件查清的事实先自行查；设计取舍、文档和目标冲突、缺少业务含义的地方才向用户追问。

## 收敛与进入规划

当能够写出清楚的项目说明时，先简要复述目标、核心价值、本期边界、关键约束及仍未知的事项，让用户能纠正理解。普通探索式对话中给出“按这个理解生成项目记录”或“继续聊”的选择；用户继续聊时，沿其新增内容追问，然后重新收敛，不能偷偷生成定稿。

这是选择是否结束探索，不是为已获授权的文件写入增加审批。如果用户已经明确表示“直接根据这些材料生成”“不用再问”或“就这样继续”，沿用该选择，不再重复问是否可以生成；仍不能把未回答的问题伪造为已确定。现有计划只需补一个缺口时，也不重新开启整套访谈。

用户不知道答案或希望暂缓时，记录未知项、影响和后续处理方式，继续能够独立推进的部分。只有下一步确实依赖这个答案时才停在该问题上，不无限重复追问。

## 暂存和续接

多轮对话需要保存上下文时，在 `.workspace/drafts/` 下记下已确定内容、当前问题和有用的上下文。已有项目记录能承载这些内容时直接更新，不另写重复笔记。

恢复时先读 `STATE.md` 及相关记录，从未完成的线索继续。探索中的想法可以先记下来，待收敛后整理成项目计划。
