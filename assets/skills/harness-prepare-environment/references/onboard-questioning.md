# 上板环境的多轮问询

## 对话方式

这是一组需要逐步收敛的决定，不是固定问卷。先读项目选择与已有环境文档，再选当前最关键的未知项提问；通常一轮一个主题，紧密相关的问题可合问。收到实际回答后更新记录，再决定下一问。多个问题已经有答案时直接复用，不为满足轮次重新提问。

已有环境可做有界只读调查，分清“发现了什么”和“用户选择什么”。安装存在不代表用户同意使用；用户指定继续已有环境时则无需逐项重问。选项只列当前可行方案，并允许自由回答。遵循 [连续追问](../../harness-new-project/references/questioning.md) 的等待、暂存和续接规则，不把算子需求重新访谈一遍。

## 1. 执行位置与 Python

先确认要准备的环境、机器/容器及准备范围；已有项目绑定直接沿用。Python 的关键决定按缺口逐轮补齐：

- 管理方式：conda、venv，或用户明确选择的其他环境。
- 复用还是新建：已有环境的名字/路径，或新环境的位置；实际 Python 解释器必须可定位。
- Python 版本：用户指定版本、项目要求，或明确委托 agent 根据依赖兼容性选择。
- 是否允许修改选定环境；共享安装不隐含允许升级。新建并不意味着要覆盖已有同名目录。

示例首问：“这次 Python 环境使用现有 conda 环境、现有 venv，还是新建？已有的话请给环境名或路径。”选择新建后，再问 conda/venv、位置与 Python 版本的剩余缺口。用户说使用现有环境时，先读取其实际配置，再讨论是否需要变化。

在 Python 选择明确前，不用当前 shell 的默认 pip 安装依赖。运行包管理命令时明确解释器，例如使用选定 Python 的 `-m pip`，不要仅凭 shell 提示符判断环境。

## 2. TileLang 与 Python 配套

依次确定：

| 对象 | 需要达成的决定 | 可自行核实的事实 |
| --- | --- | --- |
| TileLang | 使用的仓库/分支或包来源、版本、源码构建或安装包；是否使用项目专属修改 | 实际 checkout/包身份、构建要求、后端和目标支持 |
| torch | 版本与包来源，保留现有还是安装指定版本 | 已安装版本、Python ABI/平台要求、实际加载位置 |
| torch_npu | 版本与包来源，保留现有还是安装指定版本 | 配套要求、实际加载位置、目标设备支持 |
| 其他必要依赖 | 按所选源码/包声明安装的范围；已有约定可覆盖 | 依赖文件、锁文件和构建入口 |

例如先问“torch 和 torch_npu 保留当前版本，还是使用你指定的一组版本？”当前版本须来自实际读取，不能把未知值放进选项。用户没有偏好时，可提出有来源的兼容组合，等待选择；明确委托选型时按委托执行。不得把两个包版本号相同、都为最新版或 import 成功当作兼容结论。

版本组合要结合 Python、目标架构、TileLang 后端和 CANN 核对。优先读取选定仓库/包的声明和官方兼容说明；记录依据及适用版本，不在通用 skill 写死版本矩阵。CANN 尚未选择时，Python 配套可以保留为待核对方案，不必先安装再反复卸载。

## 3. CANN 的复用或安装

先调查用户指定范围内是否已有 CANN，报告可用候选的实际版本、安装位置和激活入口，然后确认“复用其中一个，还是准备独立安装”。多个安装不能自动选择当前 PATH 中的版本。

- **复用已有安装**：明确选中哪个版本/路径和激活方式，检查是否满足已选 Python 配套与 TileLang 要求。不兼容时说明具体冲突和可行调整，由用户选择或按既有选型委托处理。
- **没有安装或需要独立版本**：讨论要用的版本/发布渠道，以及安装包从哪里取得、采用什么安装方式、安装到哪里。可选方式依据实际条件提出，例如用户提供安装包、从指定来源下载，或使用已有镜像；不把 weekly、系统级安装或容器当默认答案。
- **确定执行范围**：是否允许下载、安装、修改激活配置，以及安装方式确实需要的权限。已有明确授权直接引用；不要因为某台机器曾需要提权，就普遍要求 root 或修改驱动。

安装命令和组件选择从所选包/版本的实际说明确定，不能编造统一安装命令。版本只写“weekly/最新”时，在执行前解析到确切包身份并记录；用户若已授权使用该渠道，不为解析具体构建号重复索取同一许可。缺少下载或安装条件时保留具体缺口，不私自改用其他人的环境。

## 4. 收敛、执行与续接

执行前简短汇总：在哪里准备、使用哪个 Python、TileLang/torch/torch_npu/CANN 组合、复用或安装哪些内容、怎样验证。已有授权覆盖且关键选择完整即可继续；只对尚缺的选择或新增权限提问。

用户决定与可检测事实分别落盘。DECISIONS 保存回答、来源与作用域；RESULT 保存当前待答问题、方案和下一动作；最终共享环境模板记录选定配置、实际配置与证据。无需另建一份长期问询账本。

对话中断后恢复待答问题，不能将建议值写成用户选择。用户只要求规划时交付配置提案；确实安装或测试之后才记录 installed/verified。环境正常即可结束准备，不为收集完整机器诊断额外增加探针。
