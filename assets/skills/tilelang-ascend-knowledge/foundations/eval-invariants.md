# 物理防呆评测铁律

无论使用何种工作流或执行环境，以下 7 条测量与验证底线**不可妥协**。它们防的是硬件/显存/计时层面的真实假阳性与假加速，而非文档格式问题。

## 1. 输出张量必须预填 `NaN` 哨兵

- **防什么**：核内索引/步长 bug 导致部分 tile 漏写，若复用显存恰好残留上一次合法运行结果，精度比对会误报通过。
- **怎么做**：每次精度执行前，将全部输出张量（含主输出、`LSE`、全部梯度 `dQ/dK/dV`）显式填充 `NaN`（或明确哨兵值），再核查**全部元素**无残留 `NaN` 且满足误差容限。

## 2. 独立高精度参考，禁止“候选改参考”

- 使用独立于候选实现的参考（通常在 FP32 下计算，必要时按分块/逐行防溢出），并覆盖小型可手算 case、非对齐尾块、全空/全屏蔽行、非连续 `strided` 输入与非默认 Stream。
- FP32 算子验收时显式确认是否关闭 HF32，避免低精度累加掩盖误差或歪曲峰值分母。

## 3. 动态元数据与缓存必须验证原位修改失效

- **防什么**：动态 shape / mask 元数据缓存键仅绑定指针地址或 shape，当调用方原位改写 mask/索引张量内容时，kernel 误命中旧缓存输出错误结果。
- **怎么做**：构造至少多组同地址原位修改输入内容的测试用例，确认元数据缓存能正确失效并产出与修改后内容一致的结果。

## 4. 性能必须“同批 AB/BA 配对 + 频率归一化”

- **防什么**：跨批次运行受设备温度、动态降频和背景噪声影响，同一二进制在不同批次可能漂移 5%–15%，跨批直接比耗时极易误判收益或回退。
- **怎么做**：
  - 父候选与新候选必须在**同一批次**中交替运行（如 `AB` / `BA` 多轮），每轮包含独立 warmup 与固定采样次数，记录原始样本而非仅留均值。
  - 同时记录实际运行主频，跨批对照或计算 MFU 时按实际采样频率折算（频率修正 MFU）。

## 5. 精度不通过不得进入正式性能计时

- 任何必选 case 精度失败都应立刻终止该候选的正式计时流程，保留失败反例与复现输入；严禁用存在正确性缺陷的候选产出性能数字。

## 6. 源码与生成产物哈希锁定（防静默退化）

- 对未改动的快速分支（如保持主场景 `BF16/D128` 不变而扩展其他 `dtype/head_dim`），核对生成 ASC/二进制的 **SHA-256 逐字节一致**，用确定性身份证明零回归。

## 7. 设备执行与离线解析彻底解耦

- **防什么**：耗时数十分钟甚至数小时的真机测试已经全部跑完，却因为末尾解析/统计/画图脚本的一个小异常导致整批失败或结果丢失；或将重叠执行的混合核（AIC/AIV）分角色时长错误相加。
- **怎么做**：设备侧脚本只负责**安全跑完并把原始输出/原始采样/原始 prof 文件完整落盘**；指标聚合、CSV 解析、MFU 核算与报告生成一律作为独立可重跑的离线步骤执行。多角色混合核计时始终取总跨度 `max(start + duration) - min(start)`，绝不累加重叠的 AIC 与 AIV 时长。

## 8. 工具链版本锁定与独立 JIT 缓存隔离

- **防什么**：① 完全相同的 kernel 源码在不同 TileLang wheel / CANN 小版本下可能产出截然不同的精度结果（如旧版编译器存在 lowering bug 导致数万元素超差，而新版零超差）；② 多个任务或只读容器共享默认 JIT 缓存目录导致预检失败或误复用脏二进制。
- **怎么做**：每次验证记录确切的 TileLang / CANN / 驱动版本与生成物哈希；异常精度回归优先在同板上做“同源码 × 不同工具链版本”A/B 排查；每个运行任务显式将 JIT / 编译缓存指向本次独立可写目录。
