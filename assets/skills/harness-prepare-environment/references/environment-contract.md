# 共享环境与项目使用约定

## 位置与职责

新上板环境采用 environment@2，新项目绑定采用 environment-index@2。环境类别为 onboard/simulator，本版只定义 onboard；development、device、simulation 仍用于表示节点的执行阶段，不要求分别配置三套环境。

```text
.workspace/
  environments/
    onboard/
      <environment-id>/
        ENVIRONMENT.md             # 当前描述与历史修订的索引
        revisions/<revision>.md    # 已发布的完整环境描述，不覆盖
        evidence/<evidence-id>/     # 共享验证所需的证据，按需保存
  <project>/
    ENVIRONMENT.md                 # 执行阶段绑定与本项目使用约定
    DECISIONS.md
    RESOURCE_USAGE.md
    runs/<run-id>/environment-proposals/
```

环境 ID 是与用户确定的可读目录名，在 onboard 类别内唯一；不得为空、含路径分隔符或为 `.`/`..`，解析后须位于 onboard 目录内。同名先检查身份，不覆盖；允许用户已有的命名习惯，不把项目 ID 的命名限制照搬到环境名。

[共享环境模板](../assets/templates/environment.md) 保存连接、Python 管理方式、TileLang/torch/torch_npu/CANN 的选定配置和实际身份、执行入口、共享限制与能力证据。它描述工作区可引用的环境，不代表所有项目都获准安装或运行。环境目录主要保存使用文档与证据；真实安装可在远端、容器或约定前缀，不强制搬入本地目录。

[项目绑定模板](../assets/templates/environment-index.md) 保存阶段到环境修订的映射、项目专属源码/包/构建路径、授权和资源约定的引用。development 与 device 可绑定同一描述，也可按实际链路分别绑定。允许同一用户决定覆盖多个阶段，但不能将某项目或上板的许可自动扩展到其他项目或仿真。实时余额仅在 RESOURCE_USAGE 中维护。

## 选择与问询

按 [上板环境问询](onboard-questioning.md) 多轮收敛。先确定 Python 管理方式、复用/新建及版本；再确定 TileLang、torch/torch_npu 的来源和版本，并与 CANN 的复用或安装选择一起核对。没有 CANN 时讨论安装方式、来源、版本与位置；实际操作不能先于其所依赖的用户选择。

用户选定配置与观测事实分开保存。已有回答、明确的选型委托和操作授权直接复用；没有回答的建议保持未决。配置中的命令视为代码，使用前核对实际来源和行为。敏感凭据保留在既有凭据系统，不写正文。

## 发布与共享复用

prepare 在自己的 run 输出描述与项目绑定提案，RESULT 关联决定、实际安装和探针证据。协调者核对后发布新环境修订，再更新本项目绑定；只完成访谈时保留 proposal，不发布为已验证环境。

共享环境发布前核对已有修订和正在发布的执行者；同一环境由一个协调者串行发布。发现并行变更先协调，不覆盖同名修订。环境目录 ENVIRONMENT.md 仅索引已完整写入的修订；项目直接绑定 revisions 中的确切文件与摘要，不追随可变的最新指针。这是 skill 执行约定，本版未提供环境注册器、发布锁或自动一致性检查。

被共享描述引用的实际探针记录、命令和必要输入须在环境 evidence 中保留可读副本及来源身份，不能只依赖某项目将来可能被清理的日志。证据脱敏但不伪造结果；复制改变相对位置时保留原文件，另写可解析索引，不悄悄改已记录摘要。大产物可引用有保留约定的存储位置；不可读取时如实记录缺口。

另一个项目复用环境时，先确认使用选择与授权，再核对实际解释器、安装/构建、激活入口和执行组合。身份与所需能力匹配时复用原证据，不重复完整访谈和探针；项目专属 TileLang 构建、Python 包覆盖或 CANN 改动须补验受影响部分。历史成功不等于当前可达或当前项目调用链已验证。

## 最小验证与能力状态

能力使用 `unverified / verified / blocked / stale / disabled / deferred`：未测、已验证、受阻、证据不再适用、明确不用、暂缓。blocked 附原因和解除条件，disabled/deferred 附实际决定或功能尚未接入的说明。

一条适用的小型自校验样例可覆盖包加载、编译、设备运行和输出比较；记录样例来源、输入身份、命令、执行位置、时间、退出结果与输出判定。verified 必须有当前输入身份适用的实际证据，复用时明确旧证据及未变化依据，不因文档修订号变化而机械重跑全部探针。包存在、激活成功或 import 成功各自只证明有限能力。

正式实验只要求本次依赖的能力就绪。需要性能测试时验证实际计时方式；暂不需要的 profiler 或流水采集不阻塞编译/精度工作。探针可从 unverified/stale 开始，在已确定的权限和预算内执行。环境可运行不代表目标算子正确或达标。

锁/队列按该环境与具体动作的约定执行，不把所有初始化或只读检查统一纳入设备排队。特殊机器的初始化、权限和修复步骤放其私有使用文档；普通环境不需要额外走排障链。资源忙不使编译器或既有能力证据自动失效。

## 变更、恢复与兼容

TASK 固定项目绑定及所用环境描述的快照/摘要。新增用户决定和授权撤回按实际作用域生效，旧快照不能覆盖新限制；未知作业先恢复查询，不重投。资源预留与结算按节点契约执行，余额变化不改变环境身份。

环境配置变更产生新修订，保留旧版并说明受影响能力。修订文件不能隔离真实安装：原地升级共享 Python/CANN 可能影响所有引用者；有不同版本需求时先采用独立位置或讨论共享修改范围，后续执行须核对真实身份。只修改说明或某项能力时，不宣称全部历史测量失效，也不让旧 verified 掩盖新失败。

旧 environment@1、environment-index@1 及 `.workspace/environments/<id>.md` 按原角色和路径读取，保留旧授权、探针与冻结 TASK，不自动搬迁或改写。继续使用旧绑定时，仅补本次缺失的选择；需要转为 v2 时创建新描述/绑定，标明来源与实际变化，不伪造过去问询。新环境模板只用于 onboard；已有 simulation 约定可按旧契约继续读取，完整 simulator 新契约后续设计，不凭上板结果填充仿真能力。

本次只交付技能、模板与人工/agent 检查流程；环境安装仍由已核实的实际工具执行，通用 runner 和自动发布工具未实现。
