# 算法调研要求标准 ⭐

> **单一事实源**：本文件是「算法调研要求」的权威版本（conductor Stage 1 透传文本出处）。方法论细节（参考表、四口径定义、检索纪律）见 `tilelang-op-design` skill 的 [references/algorithm-research.md](../../tilelang-op-design/references/algorithm-research.md)；两者分工：本文件 = 流程要求（必须做什么），skill reference = 执行标准（怎么做、对照什么）。

## 1. 透传文本（conductor 调度 designer 时引用）

> 设计必须先执行算法调研（skill Phase R，调研四问：等价化简公式替代 / 在线算法 / 复杂度对比 / 硬件亲和性），调研对象是**同一数学语义的算法族**——输入公式 / 源算法只是候选之一，不得当作唯一算法直接进入公式优化与 tiling；复杂度对比须覆盖四口径（FLOPs / 访存 / 扫描遍数 / 中间缓冲峰值）；「无在线变体 / 无化简公式」类负向断言必须有结构依据或参考表 / 源码 / 互联网检索佐证；本地源未覆盖时可辅以互联网检索（webfetch，若环境可用）补充候选——只取算法思路、来源可溯（URL/论文/仓库 + 访问日期）、API 存在性与性能代价仍须本地佐证/实测（纪律见 skill algorithm-research.md §6）；结论落入 DESIGN.md §1.6.0 并驱动 §1.4 与 §1.6.1–§1.6.3；迁移任务调研在源算子解读（M0）后、耦合性判定与重设计（M1）前执行，源算法已识别的优化手段不得被调研静默丢弃。

## 2. 调研四问（每问必须有明确结论）

| 问 | 内容 | 结论要求 |
|----|------|---------|
| R1 等价化简公式 | 有没有数学等价（或容差内等价）的化简公式 / 结构重排？ | 候选表**含基线**（输入公式/源算法），每候选一行等价性初判与收益方向 |
| R2 在线算法 | 有没有单遍 / 流式（online）变体？ | 明确「有」（纳入对比）或「无」（写结构依据，禁止空白断言） |
| R3 复杂度对比 | 候选间量化对比 | 四口径表：FLOPs / 访存 Bytes / 扫描遍数 / 中间缓冲峰值；基线在表；口径写清含什么不含什么；带宽受限算子不得只比 FLOPs |
| R4 硬件亲和性 | 逐候选对照 | 计算单元匹配 / 片上容量 / 对齐整除 / 静态边界 / 流水可融合性 / 跨核结构；负向淘汰按弃选论证证据规则举证 |

## 3. 调研深度分级

- 单步逐元素 / 纯搬运类：可轻量调研（四问各一行结论 + 依据）。
- 规约 / 统计 / 窗口 / 矩阵 / 多步 / 融合类：完整调研（R1 候选表 + R3 对比表 + R4 逐候选评估）。

## 4. 落位与下游约束

- 调研结论落入 `DESIGN.md` **§1.6.0**：选定算法族 + 关键依据 + 与基线的结构差异；「无更优替代」必须写明调研范围，禁止空白。
- §1.4 算法描述、§1.6.1–§1.6.3 的分析对象 = **调研选定算法**（迁移任务：经 M1 重设计落地）；不得回退到未调研的输入公式 / 源算法直译。
- 迁移任务：M1 四态处置与 §0.6 重设计对照调研结论；源算法被替换时，§0.4 已识别优化手段的意图承接逐项说明，不得静默丢弃。
- R3 并列（判定裕度小）的候选 → 交 §1.6.3 布局分析 / 实验裁决模式决胜，不得纸面拍板。

## 5. Stage 2 独立复核要求（reviewer 维度 8）

- §1.6.0 四问齐全、候选表含基线、复杂度四口径对比表齐全（机械下界由 `statectl gate 2` 核对存在性）。
- 调研结论**独立复核**：负向断言（"无在线变体/无化简公式/无更低复杂度算法"）对照 algorithm-research.md §5 参考表命中行 + 源码证据 + 同类案例逐条复核；复杂度算术独立复算（重点核对中间缓冲 GM 往返是否漏计）；选定算法与 §1.4/§3.1/§6 及迁移任务 §0.5/§0.6 处置一致；源算法优化意图承接有说明。
