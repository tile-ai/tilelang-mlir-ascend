# TileLang 开发与定位

## 版本化的 API 依据

先在本次环境绑定的 checkout 内找到 Ascend 文档、相近示例和真实 API 定义，记录路径/revision；文档冲突时看同版本实现并通过最小编译核实。无法访问对应版本资料时明确未知，不能把互相矛盾的示例拼成一个 API。

从 [TileLang 上游仓库](https://github.com/tile-ai/tilelang) 或用户指定的仓库获取资料，在实际使用的 checkout 中查找 `tilelang/ascend/README.md`、相近示例及 API 定义。仓库布局可能变化，按当前源码检索；本 skill 不指定固定 commit 或要求升级到某个版本。硬件事实以对应 SDK 和架构资料核对。

需要更详细方法时，按需读取所选版本中的 `.agents/skills/tilelang-ascend/SKILL.md`（若存在），不要求全局安装，不自动执行示例，也不以外部资料覆盖任务环境约定。

已有环境安装了 `asc-search`、`asc-npu-arch` 等工具时可按其实际入口查询，并记录知识源版本；缺失时直接查所选 SDK 的文档或源码。这些外部技能不是产品运行的隐含必需依赖。

## 最小实现

从独立参考明确每个输出与输入的关系，选择能够覆盖必选 case 的分块与 launch。逐项检查：尾部访存、规约初值、累加 dtype、同步依赖、workspace 生命周期、别名与非连续输入。需要 JIT 特化时记录特化键；不能以每个 shape 重新编译冒充单二进制动态 shape。

性能优化必须保留语义与测量范围。不能把预处理、多个 kernel 或传输开销移出协议后宣称同一指标变快。设备核数与资源限制从绑定的目标获取，不把示例的常数推广为全部型号。

## 失败定位

先归类为前端语法/类型、lowering、设备编译/链接、运行时、数值或性能问题。选择最早失败的阶段缩小复现，保存错误输入、精简源码、编译选项以及对应 IR/生成代码。

生成的 AscendC/IR 是诊断依据，最终修复要回到可重建的 TileLang 候选；直接修改生成产物的实验另记，不能说原 DSL 已通过。检查真实执行入口与 launch，而不是仅凭文件名猜 kernel。

输出比较失败先定位 shape、索引、尾部、累加和同步，不优先放宽误差。仿真死锁/超时应缩小复现，区分模型限制与候选错误；需要实卡验证时使用该节点自己的约定，不能自动换机。

## 性能假设

每轮记录“观察证据 → 瓶颈解释 → 修改 → 预期可观测变化”。profile 或仿真可以支持访存、流水、同步等假设；最终收益需在同一测量协议下由实卡数据检验。减少仿真 cycle 或单条指令冲突不自动代表整个算子加速。

## 将已选方案落实到实现

沿 analysis 的 plan_id/mechanism_id 写清四件事：任务到元素的映射、数据经过哪些存储层、同时存活的 buffer、生产者与消费者的同步。initial-and-validate 从 initial_design 做同样推导。已有方案足够具体时直接使用，不新增强制设计阶段。

资源预算使用目标版本实际容量/对齐/执行域，纳入多缓冲版本、临时值及尾部排空。可在原假设内调整 tile 和等价实现；核心算法、机制或测量边界改变时向协调者提交新方案，不能改冻结 TASK 掩盖方向变化。

| 方案目标 | 实施时验证 | 有效性证据 |
| --- | --- | --- |
| 数据复用/减少搬运 | 消费者复用同一 tile，布局转换没有抵消节省 | 生成代码中的访问与实际流量变化；端到端耗时 |
| 规约/向量化 | 索引、mask、累加与执行域正确，未意外 scalar 化 | 对应 IR/指令及全部必选精度 |
| 分块/负载均衡 | grid 覆盖、尾块和任务分配；资源占用随 tile 变化 | 逐核时间与慢 case，而非平均数单项 |
| 流水/多缓冲 | buffer 版本与所有权；异步提交、等待、排空顺序 | 实际重叠/等待证据，不能只看 DSL API 名称 |
| Cube/Vector 协作 | 数据格式、跨域交接、融合和同步边界 | 完整调用链、生成代码及目标后端实测 |

引用模板时按算子族、架构、后端、dtype/layout 与成熟度筛选。可选的 cannbot `tilelang-op-design`、`tilelang-op-develop`、`tilelang-performance-best-practices` 提供方法与示例；不存在时直接查所选 TileLang 源码。示例的标签或曾通过用例不证明本候选可用，禁止默认采用其他架构的容量、API 或环境命令。

性能退化时先核对测试可信度，再对照上述预期检查实现是否落实。冗余搬运、意外同步或未发生预期重叠属于实现线索；只有实施符合方案、精度和测量有效时，才将无收益归为思路问题。
