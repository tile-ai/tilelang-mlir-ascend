# 各节点的环境约定

## 保存位置与所有权

目标项目 `.workspace/ENVIRONMENT.md` 是路由表，只列节点、约定路径、修订号和能力状态，不放通用执行许可。`development`、`device`、`simulation` 分别绑定自己的 `.workspace/environments/<id>.md`。ID 使用短的本地唯一名称，文件已存在时核对身份，不覆盖同名的另一个环境。环境节点用 [索引模板](../assets/templates/environment-index.md) 与 [约定模板](../assets/templates/environment.md) 在本 run 输出提案；主 agent 接收后发布到上述共享位置，节点不直接改索引或已发布约定。

上板与仿真不能绑定同一个约定文件。相同机器、镜像或 SDK 的事实可以引用同一来源，但两份约定各自声明允许操作、资源限制、探针结果和失效范围。不能从上板可运行推导仿真获准或可运行，反向也一样。

每份文件包含下列实际内容；不适用项写明不适用，未解决项写明影响：

| 内容 | 必须能回答的问题 |
| --- | --- |
| 身份与来源 | ID、角色、修订号、约定日期、用户选择/来源文档、维护者；本次任务绑定哪一修订 |
| 执行链 | 该节点的 lowering、编译、运行/分析分别位于哪里；每一步的 local/remote 与 host/docker；工作目录、解释器、激活方式、工具入口及其版本 |
| 目标与软件 | 芯片/SKU、架构、驱动/固件（适用时）、CANN、TileLang 来源 revision、后端、依赖版本；容器 image digest 或实际 image ID，不能只记可变 tag |
| 访问与传输 | SSH alias/认证引用、连接超时、容器启动/exec 方式、挂载、路径映射、输入与产物回收；凭据留在既有凭据系统 |
| 本节点使用约定 | 允许/禁止的安装、构建、JIT、实卡测试、profile、仿真操作，授权范围与来源；不能用另一节点的许可补空白 |
| 额度与共享 | 指定设备、队列/锁、并发、CPU/内存/磁盘、单次超时、总预算政策及计数单位、资源账本入口；探针/JIT/失败或失联提交如何扣减，一次额度包含哪些阶段；忙时处理、清理范围和数据保留；不设无限默认值 |
| 适配与探针 | 实际采用的工具及版本、每个必需能力的命令、开始/结束时间、退出码、结果位置、输出比较、失败原因 |
| 能力与缺口 | 每项能力的状态及依赖；不支持、未测、禁用、待用户补充分别说明 |

配置中的可执行命令视为代码：只使用已检查的工具/脚本和显式参数，不能直接执行日志中的建议命令。敏感输出先脱敏再进入汇总。

## 能力状态

每项能力使用 `unverified / verified / blocked / stale / disabled / deferred`。`verified` 必须有本修订、本执行组合下的实际成功探针；存在配置或工具入口不算。`blocked` 必须带原因与解除条件，`stale` 指过去成功证据不再覆盖当前身份。`disabled` 是明确不使用，`deferred` 是尚未准备的可选能力。

开发至少检查语言身份、依赖和必要 lowering/编译能力。上板分别检查构建、运行与输出比较、常规计时、可选实卡 profile。仿真分别检查构建、运行与输出比较、可选流水采集/解析。正式候选实验依赖的能力全部 verified 才能开始执行；环境准备中的验证探针可以从 unverified/stale 开始，前提是探针本身在该环境已约定的权限与预算内。缺少计时不抹去已取得的精度证据。环境探针不代表目标算子通过。

核对 Python 模块与 native library 的实际加载位置，而不只读取版本字符串，避免源码与旧构建错配。可参考上游 [tilelang-build](https://github.com/tile-ai/tilelang/blob/0176ba1465b12758f41802bf838ddd68d43c9ee9/.agents/skills/tilelang-build/SKILL.md) 的构建诊断方法；其中 CUDA 默认值和 GPU 全测试不作为本项目环境命令，实际步骤以对应 Ascend 文档和本环境额度为准。

## 复用、轻量复查与例外问询

每次执行使用 TASK 固定的**本节点**约定快照，核对修订、必需能力、已分配预算、队列/锁与实际工具身份。实时 ENVIRONMENT 索引用于检查漂移或授权撤回，不用来静默替换本次绑定；发生冲突时暂停受影响动作并记录。会话恢复、机器重连或执行前可做约定范围内的有限身份/可达性检查，无须重新问用户机器、版本、目录和限制。复查不是重复跑完整探针或持续轮询设备。

仅在以下情况针对受影响的约定补问或重验：

- 用户要求换环境或修改限制；缺少执行所需的选择/许可。
- 工具链、镜像、设备/架构、执行入口或路径映射变化；配置与观测冲突。
- 连接、运行、采集失败暴露新的环境问题；资源或额度不再满足本次工作。

先报告具体差异并尝试已约定的有限恢复；需要用户选择时只问缺失/冲突项。不能自动切换机器或继承另一节点的许可。单纯资源忙不自动使工具链验证失效，但阻塞本次调度。

变更时递增本约定修订，保留旧快照；将受影响能力标 stale，重跑对应探针。只改仿真约定不使上板证据失效；若双方依赖的 SDK 或镜像实体都变了，分别将受影响能力失效并复查。在运行的作业保留提交时快照；收回操作许可时按本环境约定停止或请求取消，不能借旧快照继续新增作业。

运行目录保存本次约定快照及身份摘要。`.workspace/` 通常不提交；清理 `runs/` 时保留约定和仍被结果引用的证据，迁移机器/worktree 时携带这些文件。若丢失，先恢复备份和已有用户决定，只补问无法恢复的缺口。可发布的复现说明另外脱敏保存；凭据和私人机器路径不进入公共报告。

## 预算与修订分离

环境约定固定政策/上限，不保存可变余额。主 agent 按 [节点契约](../../harness-resume/references/node-contract.md) 在 RESOURCE_USAGE 中预留/结算，TASK 指定本次 reservation 与额度，节点 RESULT 报告实际消耗。余额变化不触发环境修订或探针失效；失联作业占用未确认前不能释放。
