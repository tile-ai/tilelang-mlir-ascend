# 验证证据的可信度

编写/修复验证适配、执行 verify-only、调查精度异常或测试覆盖缺口时读取。复用冻结 evaluation-plan 的参考、case、比较器和协议；以下方法帮助判断证据，不能自行修改验收标准。

## 从结论追到执行

逐项建立“契约 → 合法输入 → 独立参考 → 输出断言 → 实际执行路径 → 运行结果”的对应。可在原有 case 记录中补说明，不另建一套测试状态账本。

| 核对项 | 应有证据 | 常见缺口 |
| --- | --- | --- |
| 契约与输入 | shape/dtype/layout/属性及跨参数约束来源 | 将实现的对齐捷径当公开语义，或将非法输入当正向样例 |
| 参考独立性 | 数学定义、小型手算或独立实现；数值转换明确 | Golden 调用候选、复用同一错误索引或受到原地写入污染 |
| 断言完整性 | 每个实质输出、原地状态及受保护区域的比较 | 只检查 shape/dtype，漏掉辅助索引、计数或未覆盖区域 |
| 路径身份 | 实际导入文件、后端、编译产物、launch、运行时 shape | 导入同名旧实现、CPU 回退、padding 后未进入所声称边界 |
| 执行结果 | 每个必选 case 的实际结果、退出回执与原始证据 | 将可收集、skipped、xfail、编译成功写成设备精度通过 |

同一个测试可证明 shape 正确而尚不能证明数值正确，结论按实际断言限定。源码中有用例、被收集、实际执行与执行通过分别记录；缺失设备不能转换成已验证覆盖。

## 数值标准与反例

整数、索引、布尔、mask 和计数通常按契约精确比较；浮点沿用冻结比较器，不从别的 dtype/算子复制容差。按输出分别解释标准，关注近零、小值、相消、合法大值、长规约及特殊值。固定 seed 只保证输入可复现，不能单独证明随机分布正确。

失败时保存误差分布和最差位置，判断是否来自实现、参考、输入生成或接口歧义。参考或标准有问题时向协调者提交定义依据与反例，修订后形成新的任务/计划；不得改 Golden、放宽阈值或增加 skip 来使当前冻结验证通过。

新的断言模式若检错能力不明确，可在独立临时 fixture 中故意漏掉最后一项、交换输出或破坏受保护区域，确认测试会失败。只做能回答当前疑问的最小实验，不向用户工作实现注入缺陷，也不为简单改动建立大型故障注入体系。

## 覆盖与性能路径

按 TASK 的必选范围映射 tile 边界、动态/特化分支、布局、别名、空输入及异常拒绝。发现范围内漏测时提出补齐方案；额外诊断 case 标为补充证据，不能代替原必选集合，也不擅自扩展全集。

性能前确认完整调用链执行了相同语义：输入重置、同步、预处理、多 kernel、输出转换和计时范围均沿固定协议。Golden 初始化、首次编译、profiler 重放不混入正式计时。未命中目标 kernel 时先修复适配，再解释指标；采集内容按 [上板诊断](onboard-diagnostics.md) 交付。

证据完整后仍按既有精度/性能 gate 接收；本资料不替代 evaluate 的结构化证据或赋予设备验证资格。
