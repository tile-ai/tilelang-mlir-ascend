# Roofline 定性与仿真优先的调优节奏

本卡片防止两类高成本浪费：① 没摸清理论天花板就陷入低收益微调；② 靠盲目上卡试错消耗大量真机排队与执行时间。

## 1. 第一步：开局先定“天花板”与“绝对位置”

在开始任何优化或移植前，先完成三项对齐（结合 `ascend-roofline`）：

1. **算清有效工作量与分层 Roofline**：分别核算有效 Cube FLOPs、Vector 操作量与 GM/L2 理论流量，得出当前实现的**频率修正 MFU / BWU**。
2. **找全同场参照物**：不要只比“上一版自己的代码”。先排查同仓库已有相近实现（如另一架构分支的成熟写法）及官方库上限（如全可见场景下的 CANN 官方算子）。
3. **判断是“微调区间”还是“架构重写区间”**：
   - 若实测执行 MFU 仅 20%–30%，且有效 FLOPs 跳过比例已经接近极限（剩余无效 tile 很少），继续抠地址计算或核间负载均衡通常只有个位数甚至 <1% 收益，应直接评估**重写计算主循环**。
   - 只有当主循环架构已站上合理平台后，再切入逐项空泡压缩、事件拆分与 L2 局部性调优。

## 2. 第二步：标杆移植先做策略映射，再写代码

有高性能参考源码时，编码前必须逐项确认参考实现的关键策略并映射到候选方案：

- 任务划分与 grid 策略（静态 persistent block vs 逻辑 tile 发射）
- 数据布局与片上常驻层级（`L1`/`L0C`/`UB` 谁驻留、谁多缓冲）
- 计算与中间结果复用（如 `P` 的提前送入、`K/V` 复用顺序）
- 向量化模式（`SimdVF` vs `SimtVF`、融合边界）与累加精度（FP32 累加、关闭非预期 HF32）
- 流水与同步边界（跨 PIPE 与跨 AIC/AIV 同步）

任何偏离参考关键策略的简化都必须说明具体原因与预期性能影响；不得擅自增加“尽量不用 workspace”等未要求目标来牺牲性能。

## 3. 第三步：离线证伪优先，高确定性才上卡

按成本由低到高逐级过滤优化假设：

1. **静态建模与 CPU 模拟（秒级，零硬件消耗）**：
   - 用于核查负载分布、任务覆盖完整度、GM/L2 理论读/写流量变化、原子写冲突次数。
   - **能被流量/冲突模型定量证伪的方向直接淘汰不上卡**（参考 `patterns/falsified/`）。
2. **小分片本地仿真（分钟级，零真机排队）**：
   - 配合 `ascend950-simulation` 跑单核/单分片完整三核流水（AIC + AIV0 + AIV1），精确定位指令周期、事件等待、head 边界排空与小空泡变化。
   - 注意：小分片仿真验证的是**核内流水与正确性**，不替代大工作集 L2 局部性和整卡实测收益。
   - **CAModel `FIXP Dst:OUT` 校准提醒**：在 Ascend 950 CAModel 中，`FIXPIPE -> GM`（尤其带 FP32 atomic-add）与 `MTE2` 并发争抢模拟总线时，其延迟建模可能比真实硬件悲观 **3–4×**。若某候选在仿真里所有计算与搬运子单元（`CUBE`/`MTE1`/`MTE2`/`FIXP Dst:OUT` 净服务时长/`RVECEX`）全线下降，唯独在 `FIXP` 等待处出现长空洞，切勿仅凭仿真总时长误杀——须先用真机实测 `aic_fixpipe_ratio` 反推真实写回窗口再决定是否上卡裁决。
3. **真机配对验证 + 按需 `msprof op`（最终裁决）**：
   - 只把通过离线预检与仿真筛选的高胜率候选送真机；真机若与仿真预期不符，优先检查跨核负载长尾、L2 命中率与主频漂移。
