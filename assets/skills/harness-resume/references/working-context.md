# 工作记录与交接

记录服务于下一个执行者：读少量摘要就能继续，遇到疑问再打开对应证据。以下内容按任务需要填写，不要求空模板或额外校验程序。

## 读取入口

以目标项目 `.workspace/` 为根：

1. `STATE.md`：当前任务和下一步。
2. `REQUIREMENTS.md`：目标、case、精度和性能验收；需要背景时再读 `PROJECT.md`、`ROADMAP.md`。
3. `EXPERIMENTS.md`：相关尝试及结果，先看与当前假设有关的条目。
4. `runs/<实验编号>/`：需要核实或复现时才读详细结果、代码和日志。

一个项目有多个算子任务时，`STATE.md` 指向本次任务的需求、实验记录和运行目录，不把不同算子的结果混在一起。使用另一个 worktree 或机器接手时，要一并带上这些记录及其引用的产物；它们通常被 Git 忽略。

## 当前状态

`STATE.md` 是简短工作摘要，更新当前事实，不复制全部历史。应能回答：

- **任务与目标**：正在做哪个算子、目标与约束的链接、当前阶段。
- **当前工作候选**：源码位置和版本；若有未提交修改，注明它尚未验证或对应哪次实验。
- **最佳已验证候选**：可取回的代码与实验链接、已通过的 case；尚无候选时明确说明。
- **性能概况**：基线与最佳候选的逐 case 数据或结果表链接，单位、统计口径、测量环境，以及距目标的差距。不同环境的数据分别列出。
- **进行中工作与下一步**：任务承担者、实验目录、仍在运行的作业标识（如有）、待决问题和具体下一步。

“当前”与“最佳”分开：改了代码不代表已有结果仍适用。更新最佳候选时保留其精度和测量依据；性能未知时正常记录未知，继续能推进的分析。

## 实验历史与详细结果

`EXPERIMENTS.md` 按实验追加短记录；一次有明确问题的分析也可以是一条实验。编号只需便于引用，例如 `E001`。每条包括：

| 内容 | 对后续工作的作用 |
| --- | --- |
| 假设与父候选 | 为什么尝试，以及从哪一版出发 |
| 主要变更或分析范围 | 哪些条件发生了变化 |
| 精度与性能 | 已完成的验证、未测项、逐 case 对比和计时口径 |
| 结论 | 保留、放弃或待验证，以及原因；可用来避免重复无效路线 |
| 产物链接 | 源码、详细结果、日志或 trace 在哪里 |

`runs/<编号>/` 保存本次工作需要的材料。开始时可用 `TASK.md` 记下任务和输入；结束时 `RESULT.md` 写结论与复现方式，大日志和结果表单独保存并链接。短任务不必再写重复说明。

对测量实验，留下能够重建候选的源码快照，或可取回的 commit 加补丁；同时记录编译参数、芯片与工具链、执行位置、case/dtype/layout、预热与采样方式、测量命令和原始结果。只记录 commit 而漏掉实际参与测试的未提交修改，无法代表被测候选。

按同一协议比较基线与候选，保留慢的 case 和精度失败。仿真 cycle、设备 kernel 时长与端到端延迟分开写；只有分析没有测量时写“假设待验证”。改变目标或测量条件后说明差别，不直接覆盖旧结果。

## 子 agent 交接

主 agent 将下面这些内容作为任务说明，可以直接放进派发消息或实验目录的 `TASK.md`：

```text
任务：本次要解决的一个问题，以及何时算完成。
上下文：项目根、当前需求、父候选、相关实验和证据的路径。
约束：已确定的行为、测量方式、预算及本次可用的工具/环境。
归属：可修改的文件、专属输出目录；保留其他 agent 的修改。
返回：结论、做过的修改、精度/性能结果或未测项、证据路径、建议下一步。
```

子 agent 用新上下文读取这些材料，只补读任务相关内容。详细调查留在自己的输出目录，向主 agent 返回简短结论与路径，不回传整段日志。子 agent 写本次结果；主 agent 收到后更新共享的 `STATE.md` 和 `EXPERIMENTS.md`，采纳、放弃和失败都记录，避免多人同时改摘要。

派发新 agent 不等于并行使用硬件。并行任务各有输出目录，设备测量由主 agent 安排顺序。不能创建子 agent 时，当前 agent 直接执行同一任务并留下相同记录。
