# Operator Harness 开发路线图（ROADMAP）

目标是让 Agent 在独立安装环境中，依托清晰的算子契约、硬件透视/防呆工具与持续增长的算子知识库，完成昇腾 TileLang 算子的开发、实卡验证、优化和交付。首批语言为用户指定版本的 TileLang，首个宿主为 Codex；当前实现与验证范围见 [能力表](capabilities.md)，产品需求见 [需求](REQUIREMENTS.md)。

## 阅读说明

- 本清单**严格按推荐推进顺序排列**：越靠前越贴近当前实战痛点、投入产出比越高；越靠后越偏向中长期体系化扩展。
- 具体机器、外部工具链版本、算子验收场景与私有实验证据属于用户项目（保存在 `.workspace/`），产品仓库不打包用户私有环境，只维护可跨项目复用的通用能力、模板、知识库与校验规则。
- 每项功能交付后需补齐对应的自动化回归或真实项目验证证据后才勾选。

## 第一优先级（近期主线）：算子质量、使用体验与通用评测能力

聚焦真实算子开发中最直接影响产出上限与日常效率的通用能力，按序推进：

### 1. 算子编写质量与标杆复现

- [ ] **补齐算子编写对照样例与选型回归（完善三层知识库）**
  - **现状**：已在 `tilelang-ascend-knowledge` 落地显式 intrinsic / Stage / 自动调度选型文档、片上容量预检、物理防呆评测铁律与首批实卡模式/反例卡。
  - **待补交付**：① 同一语义下高级接口、Stage 约束、显式 intrinsic/全手动三种写法的精炼可运行对照样例（覆盖搬运、矩阵指令、FixPipe、跨 PIPE/跨核同步、缓冲初始化/复用/排空）；② 在 `PORTING`/实现方案模板固化分阶段范式选型与 SIMD/SIMT 正交记录字段；③ 单缓冲可用但多缓冲超限的容量反例检查，以及覆盖“高级已达标 / 自动流水受限切 intrinsic / 高级受限但底层可表达 / 底层不支持”四类场景的选型回归。
  - **验收**：新 Agent 在用户未显式提示时能依据参考策略自主调查并作出有证据的写法选择，以完整调用精度、性能与容量约束为判据。

- [ ] **强化 `port-baseline` 实现分析与初版性能接近门槛**
  - **问题**：当前允许纯按数学公式重写、仅精度通过但性能严重落后的实现作为初版放行。
  - **交付**：修改 `port-baseline` skill、模板与接收规则。编码前强制完成参考源码、实际分派与 tiling 分析，输出任务划分、数据布局、中间复用、向量化、累加精度、存储层级与流水同步的逐项映射；偏离关键性能设计须给依据与预期影响，禁止擅自增加“尽量不用 workspace”等未要求约束；同步补齐无性能源码时 `initial-and-validate` 对 `absolute`/`model`/`none` 目标的模型假设与适用条件记录。
  - **验收**：执行前固定逐 case 初版性能接近门槛（与最终优化目标分列）；仅当策略映射落实、全部必选精度通过且达到接近门槛才接收交付 `analysis`，否则在本节点排查修复或保存未验收检查点。

### 2. 需求入口与环境准备体验

- [ ] **需求澄清改为集中式问答入口（支持交互与 Markdown 模板）**
  - **交付**：更新 `new-project`/`onboard` 追问指南，先吸收已有决定与仓库/环境事实，再一次呈现全部待定问题；支持交互提问时优先使用，否则输出固定 Markdown 模板（已确认事项、问题编号、选项/建议、回答格式、未知项影响与最迟确认阶段）。
  - **验收**：用户可一次回复全部问题或暂缓某项；已回答事实不重复问；建议值不视为同意；两种入口生成等价决定记录。

- [ ] **完善环境模板的状态与使用约束**
  - **交付**：在共享环境、索引与项目绑定模板补齐生命周期状态（`proposal`/`active`/`blocked`/`sunset`）、状态时间/原因、最近探针证据、恢复或日落依据，以及执行身份、权限、设备/资源与缓存隔离约束；环境整体状态与逐项能力分列。
  - **验收**：新 Agent 单凭模板即可判断是否可选、允许做什么与如何排障；覆盖可用、受阻、日落样例及旧布局兼容。

- [ ] **`prepare-environment` 先盘点已有环境并优先复用**
  - **交付**：节点开始先读取已有环境索引、描述、绑定与历史验证记录，列出复用候选与缺口，区分开发可用性与正式验收配置锁，再决定直接复用、局部修复或新建。
  - **验收**：已有适用环境优先复用；新建前记录现有候选为何无法满足；明确源码、缓存与日志隔离方式。

- [ ] **提供有界的轻量环境快速探针**
  - **交付**：可执行探针脚本，先快速检查可达性、解释器/依赖/SDK 身份与兼容性，再按需执行最小编译、设备运行和输出比较，明确超时与资源上限并输出分阶段证据。
  - **验收**：快速区分可复用、可修复、暂不可达/忙和不兼容；只读检查不隐式安装或启动设备任务；import 成功不代替运行通过。

- [ ] **建立跨项目生效的环境日落（`sunset`）机制**
  - **交付**：任一项目判定某环境不可用且不可恢复时，在环境文档与索引标记 `sunset`，记录判定来源、时间、失败与恢复尝试证据、理由、影响范围及替代环境（兼容旧单文件布局）。
  - **验收**：后续项目及已绑定旧修订项目使用前均能发现并停止自动选用；暂态故障或单项目不兼容不直接日落；恢复须经新修订实测显式重启用。

- [ ] **提供通用的 host / docker 基础环境脚手架模板**
  - **交付**：提供**不含私人路径与硬编码外部版本**的通用 host 依赖清单模板与 Dockerfile 模板，帮助用户按所选工具链一键配齐 `pytest`、构建与打包等基础工具，项目专属依赖通过扩展层隔离加入（不把用户具体机器环境打包进仓库）。
  - **验收**：用户按模板生成并绑定环境后，新 Agent 可直接跑通标准测试入口，无需反复逐包拼装基础依赖；多项目复用同一基础环境且源码/缓存隔离。

### 3. 通用防呆评测与可插拔执行接口

- [ ] **提供薄防呆评测基座与可插拔 NPU 执行接口**
  - **原则**：因特定共享裸机难用而临时引入的人肉打包脚本或外部互斥胶水留在机器私有配置，**不固化进 Harness 本体**。
  - **交付**：① 将物理防呆底线（输出 `NaN` 哨兵预填、独立高精度参考、动态元数据原位改写缓存失效、同批 AB/BA 配对、主频采集与归一化、生成代码 SHA-256 锁定、设备执行与离线解析彻底解耦）沉淀为通用薄评测库/模板；② 按 [复用计划](REUSE_PLAN.md) 提供可插拔的 Onboard/DeepJIT 执行适配口，支持探测、提交、查询、取消/超时与原始产物回收，错误候选自动跳过正式计时。
  - **验收**：独立安装不依赖特定私有机器脚本；解析脚本异常不影响已落盘的原始设备样本复算；正反例与超时/断线/取消路径均可追踪。

## 第二优先级（架构待决）：工作流严格度分级、恢复与搜索纪律

> **挂钩讨论**：[GitHub Issue #271](https://github.com/tile-ai/tilelang-mlir-ascend/issues/271) 正在讨论面向强/弱不同能力模型是否拆分为 `strict` / `lite` 模式。在讨论明确“最小有效约束集”前，对以下偏重状态机与门禁的增强项采取保守推进，暂不盲目加厚复杂度。

- [ ] **完善只读状态汇总与摘要幂等重建**
  - **交付**：统一展示在途/未知作业、未结预留、待确认回执、知识失效、摘要漂移与事件水位；支持从唯一事实源幂等重建 `STATE`/`AUTOMATIC`/`RESOURCE_USAGE`；宿主控制步骤与程序准入 run 数分列显示。
  - **验收**：删除或滞后摘要后可无损重建；只读查询零写入。

- [ ] **补齐跨持久化边界的中断恢复演练**
  - **交付**：围绕启动、进程回执、设备最终回执、资源结算、accept、环境发布与摘要更新的故障注入用例。
  - **验收**：在任意边界中断后，新进程沿原 request/job 恢复，不重复执行、不重复扣额、不提前释放 unknown 资源。

- [ ] **固定多 case 权重排名与交付复验规则**
  - **交付**：在逐 case mean/median 阈值之外，为业务权重、允许退化与汇总统计定义契约，记录 best 选择理由与独立复验结果。
  - **验收**：统计口径与偏差在采样前固定，不同指标不混比，如实报告波动与退化。

- [ ] **为大预算尝试增加机制准入门槛**
  - **交付**：可配置的大预算触发条件，要求记录预期机制、历史近邻、反证、验证方法与停止条件。
  - **验收**：无新依据的重复失败方案不反复消耗预算；小规模探索保留低成本入口。

- [ ] **支持复合优化的有界消融与简化**
  - **交付**：为同时变化的多因素生成有界消融/裁剪任务并复用依赖队列管理结果。
  - **验收**：能区分各因素贡献与交互，同等质量优先更简单实现，保留失败与无收益证据。

- [ ] **建立来源复查与知识更新触发规则**
  - **交付**：按来源版本、环境变化或有效期触发 baseline 与知识库（特别是 `compiler-note` 条目）复查，记录刷新水位与后继版本。
  - **验收**：过期来源不会无提示继续支持决策；知识冷却与远端发布保留真实人工批准。

## 第三优先级（中长期按需扩展）

以下三个方向相互独立，按真实业务与对外推广需求择机启动，不阻塞前期主线：

### 1. 标准化执行包与编译产物导出（跨算子/跨环境规模化时启动）

- [ ] **定义版本化候选执行包契约**：描述语义、shape/dtype/layout/stride、容量、workspace 生命周期及多阶段同步与清理规则；未编译字段保持未知。
- [ ] **从编译产物导出 ABI 与 launch 元数据**：导出源码/二进制摘要、编译器/目标、入口/参数顺序、grid/block、mix mode、动态共享/local memory 与 stream，并用非零 local memory 与多阶段夹具核对。
- [ ] **让设备 runner 直接消费执行包**：统一包的校验、传输、加载、launch、输出回收与清理；缺失或错误 ABI/内存字段在设备执行前拒绝。
- [ ] **补齐编译缓存与跨环境产物失效规则**：将源码、编译配置、目标、工具链与执行包身份纳入缓存校验，确保同名文件改动或工具链变化不误用旧产物。

### 2. 对外分发与安装生命周期（面向外部用户推广时启动）

- [ ] **提供版本化 npm 包与 `init` 入口**：封装现有源码安装器，通过 `npx` CLI 在空目录初始化 Codex 技能，零私人路径或硬编码 commit。
- [ ] **提供只读 `doctor` 诊断命令**：只读检查安装完整性、宿主接入、运行时与环境配置缺口，不隐式安装依赖或修改用户配置。
- [ ] **实现受管卸载与配置迁移**：基于受管清单安全卸载产品文件并迁移版本化配置，保留用户修改、worktree 与实验记录。
- [ ] **保存在途任务引用的旧工具束并验证升级接续**：按在途任务引用保留所需评测代码与契约版本，确认安全回收条件。
- [ ] **完成首个独立发布全流程验收**：用真实打包产物完成安装、`doctor`、冷启动最小工作流、升级/回滚与卸载验收，明确标注未支持后端。

### 3. 全执行矩阵、仿真标准化与 MCP 外层（按机器与客户端需求启动）

- [ ] **定义共享 simulator 环境并接入首个执行后端**：建立共享仿真环境描述、依赖探针与编译/提交/查询/取消/产物回收能力，与实卡授权严格隔离。
- [ ] **打通仿真/流水采集到 `analysis` 的证据链**：基于现有 `ascend950-simulation` 增强与导出脚本绑定候选、采集配置与覆盖范围，接入 `collect-only → analysis`。
- [ ] **逐格补齐 `local/remote × host/docker` 剩余设备执行组合**：逐项核查编译/运行位置、镜像、挂载、设备映射与异常恢复，不外推支持范围。
- [ ] **按客户端接口需求提供薄 MCP 外层**：仅暴露长任务提交、查询、取消与大体积日志的产物引用读取，不在外层重复工作流决策。
