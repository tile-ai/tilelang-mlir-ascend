# 算子缺陷与优化空间

从当前候选的完整调用开始，将需求、参考算法、TileLang 实现、生成代码和逐 case 证据对齐。缺陷分析的目标是指出具体错误或性能损失的位置、条件与验证办法；资料中的优化套路只作为候选解释。

## 缺陷分流

| 问题 | 最小诊断证据 | 后续动作 |
| --- | --- | --- |
| 输入/输出契约或精度缺陷 | 首个失败 case/输出、参考与容限、误差分布；定位索引、尾块 mask、初始化、累加类型、归约顺序、别名/原地更新 | 给出可复现条件和具体修复位置，交回原 develop 修复并重验 |
| 并发/同步/实现缺陷 | 输出所有权、生产消费顺序、生命周期和越界范围；源码→IR/生成代码差异，必要时有限错误诊断 | 记录“预期行为→实际实现→影响”；保留原节点未验收状态 |
| 构建/测量/采集缺陷 | 源码/加载库/二进制身份、kernel 命中、计时/重置/重放与冻结协议差异 | 修复产生证据的节点；旧指标保留但标无效/局部，不能当成算法失败 |
| 性能机制问题 | 正确且实现符合方案的候选、逐 case 正式性能、原始指标/trace、瓶颈源码位置 | 形成最小优化实验，沿用 search-plan 和原验收契约 |
| 原因未明 | 已确认事实、仍竞争的解释、能区分解释的最小证据 | 有界 collect-only 或继续离线分析；不将未知归因为 idea |

analysis 可以诊断历史失败候选或发现已接收候选的新缺陷，提供反例和影响范围；这不改变 develop 的接收门槛。新发现的反例交协调者记录证据适用性、复查当前/最佳候选并安排修复/重验，保留历史接收记录，不自行改写冻结结果或晋升状态。正在失败的实现节点可以消费诊断建议继续修复，不通过创建 analysis 任务将失败结果“接收”为正常迭代输入。

## 建立算子阶段图

按真实调用列出 dispatch 条件、kernel/阶段、输入输出与中间张量、工作划分、同步依赖、存储层及成本。融合算子包含全部必需阶段，特别检查被移出计时区的工作及 host/AICPU 回退。比较参考与候选的算法差异，区分语义必需工作、实现新增工作和编译器生成的开销。

逐 case 家族建立问题表：shape/dtype/layout/分派、父候选与标杆的同口径耗时、主要慢阶段、证据覆盖、当前判断。小/大 shape、尾块、不连续布局、稀疏/倾斜输入按契约选取；不以一个 case 代表全部，也不要求每个 case 重采全部指标。

## 核算优化空间

1. **工作量**：列出每个张量在各阶段的读写次数、元素数和 dtype 字节；分别记语义最少流量、当前实现的重复/中间流量、profiler 实测物理流量。缓存复用、原子读改写、padding 和跨 kernel 中间量需要单列。
2. **计算量**：分开 Cube、Vector、SIMT、特殊函数、cast/索引与归约；FMA 的计数约定写清。低 FLOP 不代表低指令成本；超越函数不能直接套普通 ALU 峰值。
3. **资源与并行**：记录 tile 形状、各层存储占用、buffer 数、有效任务数、尾块、同步和独立工作量。扩大 tile/多缓冲可能减少并行度或溢出容量，需核对实际目标及编译结果。
4. **成本边界**：只有本任务芯片/核心限制、dtype、频率与计量口径匹配的带宽/算力证据才用于 `bytes / bytes_per_second`、`operations / operations_per_second`。保持秒/微秒一致。计算与搬运有重叠依据时用稳态最大项辅助估计；串行依赖、填充/排空、长尾和小任务固定成本单独讨论。
5. **可获收益**：按受影响 case、阶段在关键路径上的比例、可移除工作量与置信度排序。只有前提充分才给数值范围。实测超出模型预期时先查工作量、单位、缓存及测量口径，不为匹配结果调整常数。模型不改变冻结性能目标。

## 将瓶颈映射到 TileLang

按 [上板指标诊断](device-profile.md#从指标到当前瓶颈) 选择有证据的方向，再定位可修改的函数、参数或分派条件。常见方向包括算法/融合边界内的中间量消除、数据复用与布局、tile 与核间切分、归约策略、流水/buffer、索引与控制、特殊函数和类型转换。

实施建议需要在项目绑定的 TileLang/后端源码或例子中找到 API 和 lowering 依据；记录适用架构、资源约束、必要的编译验证。其他 TileLang 后端或 AscendC/PyPTO 的写法只能启发策略，不直接作为这里的可运行代码。缺能力的方向保留为 design-only 并写明缺口，不默认转成 AICPU/host 输入计算。

先提出能独立解释收益的最小改动。多个改动必须一起才能形成合法数据流时说明依赖，并在后续有价值且预算允许时做移除对照。输出原性能协议下的预期变化、反证、精度风险、边界/退化 case 和回退条件，按 [搜索融合](search-integration.md) 交接。
