# Harness Resume

让一次分析或优化可以由新的 agent 接手。使用 [工作记录与交接](references/working-context.md) 组织上下文，记录直接使用 Markdown。

直接接手用户任务的 agent 是主 agent，负责选题、委派和更新共享记录。收到主 agent 派发任务的子 agent 读取相关上下文后，只执行分配的工作、在专属输出目录写结果并返回；下面的主 agent 步骤不由子 agent 执行。单 agent 工作时由当前 agent 完成主 agent 的职责。

## 恢复上下文

从目标项目 `.workspace/STATE.md` 开始，读取关联的需求、相关实验条目和必要证据。先搞清楚：目标是什么，当前工作候选与最佳已验证候选分别在哪里，已测性能和未验证部分是什么，已经尝试过哪些相关优化，下一步是什么。

只展开当前任务需要的实验与日志。状态缺失时从现有代码和记录补足；找不到测量结果就记录未测，不把代码现状推导成性能结论。当前请求改变目标时沿用用户选择，并在需求和状态中注明变化。

## 主 agent 推进任务

结合历史选择下一项工作，写清要验证的假设、相关 case 和预期输出。遇到先前失败的路线，说明这次新增的依据或条件变化。开始前在状态中记下正在进行的工作和实验目录，结束时按同一编号收尾。

宿主提供子 agent 能力且允许委派时，把较长的代码调查、流水分析、实现或实验交给独立上下文的子 agent；小修改直接完成即可。主 agent 保留目标、决策和简短结果，详细检索与试错留在子任务中。没有子 agent 工具时按相同步骤在当前会话执行，记录仍可供下次接续。

派发时给出具体任务、必要约束、输入文件路径、输出目录和可修改范围，使用宿主的新上下文选项；不默认继承整段聊天。参考 [交接格式](references/working-context.md#子-agent-交接)。实现任务划定文件归属，说明还有其他 agent 工作，应保留他人的修改。共享设备的性能测量串行执行，已有设备占用机制继续使用。

主 agent 不重复子任务的调查，等待其结果后读取简短结论，按需查看证据再决定是否采用。独立的只读分析可以并行；修改同一实现的候选分开实验，不同时改共享源码。

## 主 agent 汇总与接续

一次分析或实验结束后，将假设、变更、精度、性能、结论和产物位置写入 `EXPERIMENTS.md`，失败和无收益也保留。随后更新 `STATE.md` 中的当前候选、最佳已验证候选、进行中事项和下一步。多 case 的取舍按任务约定判断，不能只凭一个最快 case 替换最佳候选。

中断时记下最后完成的步骤、正在运行的任务与结果位置；下次先查看任务是否仍在运行和已有输出，再决定继续或重跑。

最终向用户说明结果、相对目标的差距和下一步，引用可复查的记录。具体编译、实卡测试和仿真使用项目实际可用的工具；此技能提供接续与协调流程。
