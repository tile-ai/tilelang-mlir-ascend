# 标杆、kernel 与流水分析方法

## 首次标杆分析

以本任务选定并记录身份的源码与适配为起点，列出完整算法阶段、输入输出与中间存储、工作划分及同步，说明shape分派为何成立、哪些只是待验证的性能解释。将思路映射到指定TileLang后端可用表达，输出一个可执行初版方案、关键正确性风险和验证case；不把标杆语言的API或硬件假设照搬为TileLang结论。

首次可以只有源码、case与已有测量，不必有目标kernel或新trace。后续分析读取对应测试结果，聚焦一个需要解释的错误或性能差距；已有分析可以引用，但必须核对标杆、候选与测试身份。

## 仿真与流水证据

按需在任务所选的 [TileLang 仓库](https://github.com/tile-ai/tilelang) checkout 中查找 profiling 资料，例如 `.agents/skills/tilelang-ascend/references/profiling.md`；路径和方法以当前版本为准。其 npusim recipe 与项目 simulator 不是同一接口，不能直接互换命令；事件单位、配对以及 dispatch/completion 的含义须按本次实际模型和解析器核实。

## 先限定能回答什么

记录模型版本、目标架构、配置与采集覆盖：完整算子/单 kernel/单 core/片段分别说明，是否含启动、传输与清理也要说明。仿真 output comparison、流水完整性、模型 cycle 与实卡性能分别判定。

仿真与实卡可以使用不同机器、SDK 和构建产物；这样的结果用于提出解释与假设，除非有对应校准证据，不能直接作定量加速比。静态模型也不能替代动态执行或精度验证。

## 分析顺序

根据问题选取必要项，不默认做全量分析：

1. 核对实际 kernel、block/core 与输出范围。用原始事件/时间线确认 parser 摘要没有漏掉目标部分。
2. 看关键路径：计算、数据搬运、同步/等待与串行段；并行段的时间不能直接相加。
3. 对访存问题注明地址空间、访问粒度、活跃 lane、布局和模型假设。UB 冲突结论不能直接推广到 GM/cache。
4. 把指令或片段成本对应回源码、IR 或生成代码，给出可以改变的具体因素；没有映射时保留不确定性。
5. 提出一个可证伪假设和最小改动，说明预期 trace 变化，以及需要哪些实卡 case 检验收益与退化。

优先使用 simulator 随版本提供的解析工具，记录解析器版本与命令；工具缺失时直接检查有限原始证据，并写明没有验证的指标。不要用猜测的字段填补输出。

## 结果格式

`RESULT.md` 写清：首次/后续分析、问题、确切标杆/候选与测试身份、实际使用的环境或历史产物、覆盖范围、主要观测及原始位置、解释与限制、交给develop的方案/假设和验证计划。执行仿真时补充simulation约定、输出比较和trace完整性；没有采集时如实写not_run/not_applicable。

例如“在所采集 core 的区间中观察到等待事件，怀疑生产/消费同步导致空泡；改变一个流水参数后重验”，是可执行假设。没有全范围数据时，不写“整个算子受同步限制”。cycle 下降也不能写成已取得同幅度实卡加速。

## 上板流水与指标

优先消费 develop 的 ANALYSIS_DATA，采集来源与语义见 [上板诊断](../../harness-develop/references/onboard-diagnostics.md)。先检查候选/构建/case/环境、真实 kernel 和阶段映射、重放模式及实际 core/pipe 范围，再解释数据；原生 profiler 的调用时间线与 msprof op 的单核流水不是同一种证据。

完整多指标报告由 msopprof 的 PMU 分组重放及专项流水/插桩共同产生；原生 torch_npu 只补充调用映射和基础指标。先区分同一 pass 内的事件与跨重放统计，不能将后者拼成同时发生的流水；核对工具跟踪内存的恢复、L2 和任务队列等运行差异。复用工具的指标计算与字段解释，不根据指标名字猜测采集次数，也不把所有采集当作同一次未插桩执行。

- PipeTimeline：观察 MTE2/V/MTE3（以及实际出现的 Cube/FIXP 等）空隙、重叠和等待，结合数据依赖判断 multibuffer 或同步改动是否有价值。采样空白不自动等于整个核空闲。
- PipeUtilization/Memory：核对忙碌比例、实际读写流量、带宽统计分母和单位。比例高不能单独证明与另一通道重叠，带宽低也可能来自访问离散或并发不足。
- Occupancy：比较实际采集物理核的耗时和流量分布，检查分片、尾块与工作量倾斜；这是工具的核间负载视图，不直接等于 warp occupancy，也不由图上显示核数推断 grid。
- Roofline：结合真实运算量、流量、dtype 与计算/带宽上限看相对位置；它是模型辅助判断，不直接作为性能达标结论。

每个结论链接原始表格行、trace 事件/core/pipe 或官方查看器视图，说明覆盖限制，再映射到源码/IR/生成代码。输出具体下一假设及预期指标变化。没有某项数据就标缺口，不能填零或猜测；仅在现有证据确实不足时给出有界 collect-only 补采任务。精度/实现故障仍按 develop 的验收规则在原节点解决。
