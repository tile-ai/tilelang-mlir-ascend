# 资产复用与迁移计划

本计划描述可复用能力及适配边界，不规定外部项目的 commit。来源、路径和版本由用户项目配置；执行前按实际安装内容核对接口，任务证据保存在用户项目的私有记录中。

## 1. 复用对象

| 来源 | 资料与能力 | 用途 |
| --- | --- | --- |
| [TileLang](https://github.com/tile-ai/tilelang) | Ascend文档、示例、API及构建/profiling资料 | 首批语言、lowering与调试方法 |
| [asc-devkit](https://gitcode.com/cann/asc-devkit) | SDK、架构资料及相关技能 | 生成代码诊断和硬件能力核查 |
| 用户配置的 simulator | 模型执行、trace及解析工具 | 可选仿真与流水分析 |
| 用户配置的 Onboard/DeepJIT | 编译、远端传输、设备执行及采集 | 实卡执行适配 |
| [GSD Core](https://github.com/open-gsd/gsd-core) | 需求讨论、阶段组织与持久状态方法 | 初始化与接续流程参考 |

下文接口名称用于说明适配职责，具体实现和目录随来源版本变化。先检查实际接口，再实现适配；不从项目名称或资料存在推断平台支持。复制外部文件时核对许可证并保留声明。

## 2. Skills：按职责迁移

首批仅接入TileLang；AscendC资料可辅助理解生成代码和底层调试，完整AscendC开发入口留待后续。

| 能力 | 适配方式 |
| --- | --- |
| 需求分析与API核验 | 提取通用方法，API查询仍以当前语言/SDK为准 |
| 架构与产品映射 | 共用结构化来源，按实际目标核查资源与能力 |
| 文档检索 | 显式配置知识源路径，检查索引新鲜度和覆盖范围 |
| kernel调试 | 核对输出链路、同步与instrumentation清理，区分调试和profiling |
| API单测生成、devkit文档规范 | 不直接迁移为通用算子验收标准 |
| 外部仓库发布流程 | 不作为算子生成核心依赖 |

迁移时去除对来源仓库目录层级、命令工作目录和其他私有技能的隐含依赖；技能缺失时可直接查对应版本源码和文档。产品技能放入 `assets/skills/`，由安装器接入宿主发现路径。

## 3. Simulator：执行、分析与任务接口

适配层应连接模型运行、流水采集、周期分析及已有解析工具，而不是重新实现仿真器。执行位置与隔离方式分别配置，host/docker和本地/远程逐项验证。

需要验证：

- 命令分派、环境加载、锁/资源约定、超时和失败返回码。
- 结构化任务状态、原始/部分trace、产物清单和错误类别。
- 远端提交、传输、取消、回收和清理确认。
- 镜像、架构、频率、工具链和解析器的实际身份，避免把示例默认值推广为平台事实。
- 候选、编译产物和采集范围的关联；残缺trace只能支持相应范围的分析。

M2优先建设候选执行契约与设备工具，M4在其基础上扩展仿真MCP；已有工具宣称支持某项能力仍需实际适配验收。

## 4. Onboard/DeepJIT：编译与设备执行

目标适配链路：TileLang lowering → 生成源码/IR和执行元数据 → 按环境编译 → 传输与加载 → launch/同步 → 完整输出及采集回收。可复用语言入口、源码与头文件打包、编译缓存、缓冲区传输和设备执行能力，具体API以用户配置版本为准。

| 契约关注点 | 适配要求 |
| --- | --- |
| 客户端lowering与远端编译 | 分别记录依赖和执行位置，不默认承诺客户端零SDK |
| SSH与Docker | 显式区分位置和隔离方式，核对挂载、设备映射及退出传播 |
| 入口、ABI和launch | 从编译产物导出执行包，不让调用方猜参数顺序、grid或动态内存 |
| 编译缓存 | 校验源码、目标、配置和工具链身份，不能仅按文件名复用 |
| 完整调用与采样 | 显式处理初始化、预热、缓存、同步、重复和统计，不以单kernel耗时代替多阶段算子 |
| 性能与流水诊断 | 分别定义计时范围、采集配置和有效性，不混用指标 |
| 超时与断线 | 保存原job身份并查询/回收，不自动重放设备副作用 |

先通过小型任务验证接口、普通内核编译和输出比较，再验证性能协议。共享依赖更新或重构单独确定范围，不将环境准备隐式扩成大型构建。

## 5. GSD：参考流程，独立实现

`harness-new-project` 与 `harness-onboard` 借鉴需求澄清、阶段覆盖和持久状态方法，由本项目独立实现；不依赖GSD runtime、不保留其命令别名、不自动提交。来源与许可见 [provenance](../assets/skills/harness-new-project/references/provenance.md)。

通用阶段完成或Ship语义不能直接作为算子达标判据。正确性、性能统计、身份一致性和证据失效需要独立检查；宿主子agent可用于上下文隔离，但不意味着已有独立后台调度服务。

## 6. 复用完成条件

每项资产经过“来源和接口明确 → 契约适配 → 单独调用验证 → harness端到端验证”。安装成功、配置存在、文档描述或编译通过均不替代实际输出比较。

节点职责见 [四节点设计](nodes/design.md)，方法资料见 [技能来源](nodes/skill-sources.md)。默认按 `establish-baseline → analysis → develop → analysis` 推进，仿真是否执行由具体问题和预算决定；后续实现按 [路线图](ROADMAP.md) 安排。
