# 首轮工作流试用总结

2026-11-03，以 MoEPermuteAlignFwdOp 为真实任务，由主 agent 协调独立的 GPT-6.1 Terra/high 节点进行试用。用户接受工作流与测试环节，本轮观察结束；环境恢复、算子进一步调优和最终交付留待后续。工作流可用性与算子性能达标分别评价。

## 已实施与实际证据

| 环节 | 本轮产出 |
| --- | --- |
| 需求与环境 | 固定12项必测、逐项≥1.0x、逐shape分派、实现限制及用户允许的Triton fallback；开发、上板和仿真分别记录约定。 |

默认循环已统一为 `establish-baseline → analysis → develop → device-test → analysis …`，达标或遇到停止条件时收尾。节点内部问询可以续办，后续节点使用独立上下文。

## 暴露的问题与改进方向

- **执行信息仍需手工重组。** launch动态内存字段出现丢失，ABI/grid/stream与源码摘要仍散落在文字和清单中。需要MCP与版本化执行包，由编译端导出并在执行前校验。
- **runner重复适配易错。** 曾出现shell只读变量导致退出码遗漏、回收写入约定目录之外、上传权限错误；统一工具应负责前台执行、私有目录、退出传播及回执，不能只增加文字提醒。
- **诊断与环境路由需要更准确。** 一次设备对照在静态接口核查后即返回分析；一次NPU初始化故障被节点推荐送入kernel分析，由主协调者修正。需表达失败阶段与实际执行范围，analysis也应提前有界确认实验可行性。
- **记录仍依赖模型主动保存。** 曾先产生lowering产物、后写RESULT，部分环境输出只在会话中；工具应自动创建检查点并保存原始证据，当前导航从已接收结果更新。
- **环境政策不能跨机器照搬。** 初始化应引导进入prepare-environment；锁、设备映射和构建限制按当前环境及用户覆盖决定传递。普通算子编译与大型CPU构建分别处理。

具体优先顺序和验收条件见 [路线图M2](ROADMAP.md#m2单算子开发与验证闭环)。这些是待实现的工具能力，不因本轮试用被接受而自动完成。

## 停止状态与结论边界

automatic共占用7/8控制步，提交2/4设备作业；两个950DT作业均在获锁后初始化失败并已退出。A5只做只读环境检查，未提交设备作业。用户确认试用充分后主动停止，保存为paused，无本任务在途事项；停止并非排队超时或控制额度耗尽。

历史C001结果保留，C002设备验证仍待继续。生产Op/JIT、全部性能目标和提交/PR均未完成；历史跨软件栈比较边界也未解除。试用说明skill加脚本及主agent协调能够推进工作，但尚未证明通用MCP、程序gate或自动优化到全部性能达标。

原始运行文件保留于各项目的私有`.workspace/`，不随发布包提交。后续从项目STATE、RESUME、DECISIONS与资源账本接续，不能仅凭当前源码推断历史测试，也不为继续观察流程而无限扩展环境排查。
