# 实卡验证协议

方法参考：[TileLang profiling](https://github.com/tile-ai/tilelang/blob/0176ba1465b12758f41802bf838ddd68d43c9ee9/.agents/skills/tilelang-ascend/references/profiling.md) 与 [Hugging Face triton-kernels](https://github.com/huggingface/kernels/blob/633d1faef0caea5f2b9acf447e17ad5f840a52d1/kernel-builder/skills/triton-kernels/SKILL.md)。只借鉴测量边界、独立参考和边界 case 方法；不引入 CUDA/Triton 命令或硬件假设。实际计时实现要核对当前版本，kernel duration 的聚合不自动代表完整算子墙钟延迟。

## 正确性

任务契约先确定 case ID、shape、dtype、layout/stride、输入分布/seed、参考实现、输出比较算法与容限、NaN/Inf 规则、确定性要求。测试程序应检查输出数量、shape、dtype，以及全部要求的值；缺输出和未覆盖 case 不算通过。

同时用小型可核对样例或数学不变量验证参考。保留每 case 结果、误差统计/位置、实际失败输入或确切生成脚本及 seed。环境最小探针与目标算子精度是两份证据。精度失败后可以为了定位问题另做诊断采集，但不得进入常规性能验收或更新最佳候选。

## 测量协议

在采样前从需求与已有协议确定以下内容，未知且影响验收时询问测量要求，不重问环境：

- 单 kernel、完整算子或含传输的端到端范围；多 kernel 和流水重叠以实际依赖与同步测量整体时长，不简单累加任务耗时。
- 计时机制与单位、stream/同步边界、预热数、采样数/批次、重复次数、输入输出重置、冷热缓存策略和统计量。
- 基线与候选的执行顺序、可比环境、负载判断、样本无效判据和有界重试规则。
- 逐 case 目标、汇总方法/权重、允许的退化、workspace 上限和预算停止条件。

首次 JIT、数据准备和采集开销单独记录；是否计入端到端范围由协议决定。涉及原地更新、累加输出或随机状态时，每次运行按相同规则重置。基线与候选使用相同输入条件与计时范围。

只按预先规定的规则剔除样本，并保留原始数据与理由，不能只保留最快几次。报告每 case 的统计量、离散程度和样本数；记录可获得的负载证据，没有独占条件时说明性能结论边界。负载检查遵循 device 约定，不自行添加持续设备监控。

没有可用基线时报告绝对耗时，只有用户已确定的绝对指标可以用于判定达标。使用旧基线前核对任务、输入、协议、工具链和设备身份；不匹配时重测，不能混用不同机器结果。

## 判定与证据失效

编译、精度、性能分别记录 `passed / failed / not_run / invalid`，必要时附阻塞原因。性能 `passed` 还需要满足任务的目标，不等同“采到了数据”。任务级状态由必选 case 汇总，不能拿单个最快 case 覆盖其他失败。

候选源码/依赖、编译选项、launch 改变会使该候选旧精度和性能不再适用；参考/容限改变使精度需要重验；设备环境或测量协议改变使受影响基线和候选测量需要重跑。仿真约定单独变化，不自动影响上板证据。
