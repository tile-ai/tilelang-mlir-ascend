# 下一步选择与推进

`harness-status`、`harness-next`、`harness-automatic` 共用本规则，避免三个入口各自猜工作流。它是宿主 agent 执行的选择与接收流程，不是已实现的程序 gate；具体节点遵循 [节点契约](node-contract.md)。

## 1. 读取与判断

先确定用户指定的项目/任务；未指定时使用 STATE 的当前任务。读取 STATE、需求及最新决定，按需展开当前 run/RESULT、候选、环境索引/快照、资源账本与 AUTOMATIC 记录。一个项目存在多个未选择的任务时，不任选一个执行；status 报告歧义和最小选择问题，next/automatic 才实际问询。

STATE 的“下一步”是导航提示，不能覆盖实际证据。核对任务版本、当前候选和最佳候选、已接收结果及未接收交付、agent/job 状态、必选 case 覆盖、授权/能力和剩余预算。只展开相关记录，不要求先重查全仓或重新问环境。无记录时，status 只说明缺口并建议 new-project/onboard；next 可以在当前调用开始对应初始化/澄清动作。

每次得到一个选择，至少说明：**动作、原因与证据、依赖/缺口、完成或停止条件**。给一个主推荐；受阻时可另列一项独立可做的工作，不列一串无法取舍的候选。

## 2. 优先级与边界

先处理用户本次明确范围与停止指令，再按下表找第一个适用动作；只对当前目标的必需条件应用门槛。只写代码不要求设备通过，分析旧 trace 不要求新仿真环境 ready，可选仿真不能阻塞实卡主路径。

| 记录状态 | 下一步动作 | 不应发生 |
| --- | --- | --- |
| 同一任务已有活跃协调者/节点或外部 job | 加入/等待原执行者，或在约定范围内查询并恢复原 job；记录未知时先核实 | 另起协调者、重投 job、清空额度 |
| 已有终态 RESULT 尚未接收 | 检查交付与身份，接收或给出补充要求，结算并更新共享记录 | 跳过现有交付重新做一遍 |
| 已满足本次目标且在途事项已交代 | 汇总交付，推荐结束/由用户选择新任务 | 自动扩大到下一算子或路线图全部阶段 |
| 目标/语义/关键许可缺失或冲突 | 继续已有问题，或记录并询问最小缺口 | 把推荐答案、超时或自动模式当授权 |
| 当前目标需要的环境缺失/漂移 | 环境准备节点补齐受影响能力/约定 | 重问已确定的两侧环境或静默换环境 |
| 候选/参考/case/构建入口不齐 | develop 创建、补齐或修复交接材料 | 用空目录或编译成功当精度证明 |
| 必选精度缺失或对应旧身份 | device-test 验证当前候选全部必选 case | 先做常规性能或借用旧候选 pass |
| 当前候选精度失败/构建错误 | 带反例/日志返回 develop；需要定位时另立有界分析任务 | 放宽容限、反复测试未改候选 |
| 精度通过、任务要求性能且证据不足 | device-test 按固定协议测基线/候选 | 将 profile 或仿真 cycle 当常规性能 |
| 性能未达目标或用户明确要求分析 | 根据证据提出单个假设，选择 develop 或有明确问题的 simulate | 为走流程强制仿真、无假设无限调参 |
| 工具/资源不可用、预算已耗尽、无可执行修复 | 明确 blocker、已完成部分和解除条件；有独立授权工作时仅推进该部分 | 声称任务达标或自动增加预算 |

优先级不是机械状态机。精度已失败时选择修复，不把它误判成“精度缺失”再跑；需求只要求静态交付时按其完成条件结束。已经准备好的 TASK 可用于下一步，但仍要检查它符合当前目标、输入身份和最新限制，不因文件存在就执行。

预算影响执行可行性，不应阻止只读报告、接收已有结果或有权限的原作业恢复。恢复不能扩大权限，unknown 占用不释放。某步依赖缺失时只能做记录允许的独立部分，不悄悄切换目标。

## 3. status 的只读投影

默认只读取项目记录，不写 STATE、RESULT、AUTOMATIC、账本或新 TASK，不派发 agent、启动探针/编译/实验，也不自动修复记录。用户额外明确要求实时查询时，才按已有环境约定做有限只读查询，说明观测时间；未查询时称“记录显示”，不能把历史 running 当已确认活跃。

建议报告：任务/目标、已完成与当前阶段、当前/最佳候选及证据边界、在途/阻塞/预算、一个推荐下一步及理由。缺失/陈旧记录直接说明，不伪造进度百分比。automatic 的状态、已用步数和停止原因如有则一起报告。status 不是用户授权继续，也不会改变 automatic 的模式。

## 4. next 的一次推进

`next` 是行动请求，不是再给一次建议。先复核上述选择，然后直接执行一个有明确完成条件的动作：

- 一次节点任务，包含其内部必要编译/比较/采样与接收；
- 接收已有交付、恢复已有作业或一轮必要问询；
- 当前目标已经完成时汇总结束，不创造新工作。

准备或复用 TASK、核对环境/额度，按 resume 执行并接收。可以当前 agent 完成，也可以委派；没有子 agent 工具不阻塞。节点内部有问询时保存问题和答案，能够在同一步继续就继续；等待必要回答时停在 needs_input，不当作完成。

一个节点完成后的共享记录更新属于本步，不再自动进入下一个节点。结束时报告做了什么、结果/未测项和新的推荐下一步。输入不足时真正发起最小问题，而不是只说“建议先问用户”。若只能查询到原 job 仍在运行，保留在途状态，本次 next 不重复提交。

## 5. automatic 的连续推进

automatic 重复执行同一选择和一次推进逻辑；循环与保存方式见 [automatic](../../harness-automatic/SKILL.md)。它额外管理控制步数、协调者归属与停止条件，不另设一套节点阶段，不调用 status 后把自然语言建议盲目当命令。

status 在自动模式中仍是只读查询。用户在运行中要求 next，当前协调者先保存单步意图，再完成当前有界动作并返回，连续模式转为 paused，不另开第二个循环。用户要求暂停/停止时不再派发新节点，保存在途作业和额度；取消外部作业仅按其明确要求及已有约定执行。

模式请求先按下节落盘，再等待动作结束。节点内部能继续下一操作，不表示可以忽略暂停；四节点都遵守契约中的协作停止检查点。

一份结果不是仅凭 agent 的 completed 就被接收：检查 TASK 的必交付、摘要/身份、各项实际判定、作业和预算。结果不完整时保留文件并写具体补充任务；同一原因、相同输入且没有新证据不能自动无限重试。

## 6. 模式切换与接管

执行模式、批次停止原因、节点状态和外部作业状态分别记录。模式改变由当前协调者写入 DECISIONS（请求来源、任务/run 作用域、决定 ID），AUTOMATIC 如有则引用该决定并保存尚未完成的切换；普通 next 可在 STATE 记录，不为它空建批次。先保存请求，再通知节点和等待，避免等待期间中断后丢失用户意图。后续回答问题不覆盖已保存的暂停/单步请求。

| 用户请求 | 当前动作与后续边界 |
| --- | --- |
| status / 进度如何 | 只读报告，保留当前模式；在活跃 automatic 中报告后继续原工作。另一个只读查询者不接管控制权 |
| 只看状态，先别继续 | 先由协调者执行显式暂停，再按 status 只读报告；不能把暂停指令丢掉，也不能把普通 status 当暂停 |
| automatic → next | 立即记录单步请求及它绑定的 run/步骤；有在途动作或待接收交付时，它就是这一步。无当前动作时最多新做一步，受剩余额度限制。到完成、needs_input 或 blocked 边界即返回并保持连续模式 paused，不因尚未完成又启动另一动作 |
| 暂停 / 停止 | 立即停止新增派发，并通知活跃节点在下一个安全检查点停止新操作；保存已启动调用/job，按原约定做必要记录/回收。不能等待整个多实验节点做完才响应，也不能声称外部作业已取消 |
| next / paused → automatic | 用户明确请求才启用连续模式；先处理原在途动作及结果，不能重建任务重跑。有原批次额度则沿用，已耗尽时只在用户明确继续授权后另建有限批次并链接前批。将原 next 动作接入新批次时，以一个接续步骤记录并计数，不再派发同一节点 |

另一入口发现仍活跃的协调者时，只将执行/切换请求交给原协调者；无法通信或确认归属时报告具体阻塞，不竞争修改共享文件。原协调者确定已退出后才接管协调记录；节点仍活跃则保留它，只恢复等待/沟通。只有替换节点执行者才须确认该节点已停止写入，不能把“更换协调者”和“重启节点”混同。

next 的一次请求不是资源加额。继续 paused 批次原步骤不重复计数；独立的新 next 动作记录为本次单步授权，不清零或伪造旧批次余量。耗尽的设备/仿真额度仍阻塞相应新操作，不能借换模式或批次绕过。
