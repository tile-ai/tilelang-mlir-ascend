# TileLang Ascend 编写范式选型与存储预算

本卡片解决两类高频失误：① 盲目用简化公式 + 默认自动调度导致关键性能设计丢失；② 将高级接口限制误判为底层硬件/后端能力缺口，或未核对片上物理容量就直接上卡。

## 1. 两个正交维度：不要混为一谈

编码前必须按**计算阶段**分别确定以下两个独立维度：

| 维度 | 可选路径 | 说明 |
| --- | --- | --- |
| **执行单元与向量模式** | Cube / SIMD (`SimdVF`) / SIMT (`SimtVF`) | 决定算术与访存落在哪个物理引擎。连续 UB 向量算术优先 SIMD；不规则索引/原子操作/特殊控制流再评估 SIMT，不把 GPU 线程循环机械改写为 SIMT。 |
| **指令与流水控制方式** | 高级 Op + 自动调度 / `T.Stage` 约束 / 显式 intrinsic + 手动同步协议 | 决定指令选择、buffer 生命周期与跨 PIPE/跨核同步由编译器还是开发者控制。允许**同一算子不同阶段混用**。 |

> 局部使用某条 SIMD intrinsic 不等于整条 kernel 已转为显式流水；必须明确写出哪几段交给编译器、哪几段由手动事件/槽位控制。

## 2. 三种编写路径的选择与切换准则

| 路径 | 适用边界 | 切换信号（何时不要硬扛） |
| --- | --- | --- |
| **路径 A：高级接口 + `T.Pipelined` 自动调度** | 常规 GEMM、规整归约、结构清晰的中等复杂度算子；高级接口已能达到目标 MFU 且无明显冗余同步。 | 生成代码中流水未真正重叠、出现多余同步或 `PrepareMultiBuffer` 失败、或反复调 tile/num_stages 仍无法消除明显空泡。 |
| **路径 B：Stage / Buffer 版本约束** | 整体可由编译器调度，但需显式固定循环携带状态（如 online softmax 的 `m/l/O`）与多版本 scratch 边界（配合 `tilelang-ascend-generation`）。 | 跨阶段精确复用（如 `L1` 多槽环、拆分 `Q/dO` 就绪事件、尾段提前 `FIXP` 写回）无法通过注解准确表达。 |
| **路径 C：显式 intrinsic + 手动缓冲/同步协议** | 移植高性能 AscendC/标杆算子、或需要打满硬件吞吐的混合 Cube/Vector 算子（如 Attention、复杂融合算子）。 | **并非强制默认**；仅在需要精确控制搬运、布局转置、片上复用与 flag 流水时选用，且仍须核对 lowering 与生成 ASC。 |

### 强制切换核查原则
- 发现高级 API 布局限制、自动同步冗余或流水未落实时，**不得直接宣称底层不支持**，必须核查对应显式 intrinsic / 手动事件协议在当前绑定版本中的可行性，给出继续或切换的有界实验依据。
- 移植高性能标杆时，“最小初版”指**保留标杆核心并行划分、数据复用与流水骨架的最小可验证版本**，不得以丢弃复用和流水的纯公式重写冒充移植完成。

## 3. 上板前静态片上存储容量核算（强制预检）

**编译或 lowering 通过不等于片上容量合法。** 特别是从单缓冲切到多缓冲，或为消除别名拆出独立布局时，必须按目标芯片的真实片上容量逐域核算：

1. **逐域列账**：分别核算 `UB`、`L1`、`L0A`、`L0B`、`L0C` 的物理字节数。
2. **用物理尺寸而非逻辑尺寸**：计入对齐 padding（如 32B/256B/16×16 fractal 块）、`num_stages` 或手动槽位数（如 `ring4`、`dq_c[2]`）、隐式转换临时区与运行时保留区。
3. **核对生成代码偏移与访存范围**：检查实际生成的 ASC/IR 中各 buffer 的物理分配偏移和读写范围；注意多缓冲版本下每个槽位完整读区域的初始化，避免读取未初始化 padding。
4. **单缓冲可用 ≠ 多缓冲安全**：新增 `L1` 环槽或 `L0C` 双缓冲时，必须把所有并发存活的 buffer 同时加总校验，并在 `D=192/256` 等大维度上单独验证是否需要降 tile 或降槽数。
