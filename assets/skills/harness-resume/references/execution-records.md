# 节点执行与证据记录

当前用 Markdown 与实际工具产物保存记录；此文约定内容，不表示统一执行器或自动 gate 已实现。优先使用现有工具的结构化结果文件，摘要链接到原始文件，不重新手抄大表。

## 一次执行必须能追溯的内容

每次节点都按 [节点契约](node-contract.md) 实例化 TASK 与 RESULT；生成候选时增加 CANDIDATE。以下信息放入模板或其链接的真实工具 manifest，不要求再手抄一套字段：

| 记录 | 内容 |
| --- | --- |
| 请求 | 节点、分析假设、任务修订、必选 case、父候选、预算与停止条件 |
| 候选 | 可取回源码快照，或 commit 加完整补丁（含未跟踪输入文件）；依赖、构建选项、入口/ABI/launch、生成物关系与文件摘要 |
| 验证依据 | 参考实现、case/实际输入或 seed、比较方法/容限、性能基线和测量协议的版本或摘要 |
| 环境 | 该节点绑定的约定 ID/修订、提交时副本、实际工具链/目标/镜像身份；编译与执行位置分别记录 |
| 作业 | 实际命令/参数、开始/结束时间、工具作业 ID、状态、退出码、日志、远端产物位置和回收完整性 |
| 结论 | 编译、精度、性能目标、采集完整性分别判定，失败/未运行/无效项及原因；下一步 |

产物摘要可用 SHA-256，源码包含所有实际参与构建的修改；只记 Git HEAD 不足以标识脏工作区。缓存命中也要保留其输入身份，不能跳过比较。

## 长任务恢复

执行状态与验证结论分开：作业完成不等于结果通过。提交前记录 request ID 与提交意图，提交后立即保存实际作业 ID；没有可查询 ID 的工具记录可确认的进程/容器及启动日志，不伪造远程可恢复能力。

断线或超时后先查询作业是否仍在运行，核对输出是否完整，再决定回收、取消或重试。状态无法确定时记 `unknown` 并阻止重复提交；取消请求发出不代表已经取消。只清理本任务约定范围内的资源，不删除仍被证据引用的产物。

运行中采用提交时快照，配置变更不得覆盖旧证据；权限收回仍约束后续执行。新候选、编译参数或环境修订有新记录，不能把旧通过状态写到新身份上。

## 汇总与交接

委派子 agent 只写本 run 的 RESULT 和指定产物；协调角色（单 agent 时由当前执行者承担）按 [工作记录与交接](working-context.md) 检查后更新 `EXPERIMENTS.md` 和 `STATE.md`，并结算资源账本。下一节点读取新的 TASK 与这些产物，可以由当前或全新 agent 执行；消息通知不能替代落盘记录。当前候选与最佳已验证候选分开维护。

本地环境路径与访问方式保留在私有实验记录；公共交付只带必要的脱敏复现信息。迁移工作区时携带约定和引用证据，不能仅移动代码。
