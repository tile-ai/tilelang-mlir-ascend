# Harness 工程缺陷追踪

正文只记录活跃缺口；字段与操作以 [执行控制](../assets/skills/harness-resume/references/execution-control.md)、[评测入口](../assets/skills/harness-develop/references/evaluation-runner.md) 和 [升级说明](installation-upgrades.md) 为准。

## 当前状态

第二轮 review 指出的主要问题成立：首轮补上了验收规则，却没有配套的证据生成路径；历史材料检查又扩大成了整个账本的可用性依赖。本轮已将本地执行、冻结参考/比较器、采集、证据生成和控制账本接通，并把历史完整性扫描与日常恢复分离。

当前可运行的是本机 Python 适配闭环，已用真实 CPU 子进程验证正确/错误候选。torch_npu 测量和诊断脚本已接入统一证据输出，真实 NPU 环境仍需完成适配及验收。

## 活跃缺口

### G01（P1）：真实硬件执行组合尚未贯通验收

本地评测入口会执行已冻结的项目适配器；编译器 ABI/launch 元数据导出、远端/容器执行、设备锁与逐层退出仍需实现具体后端。需要在一个实际昇腾环境证明完整输入输出、同步/融合边界、正确性比较、正式性能样本与回执一致，并覆盖初始化失败、非零退出和断线。

验收：从干净安装完成一个正确候选和一个错误候选；失败不会进入正式性能测量，控制端断线后恢复原请求。后续执行矩阵按实际通过组合扩展。

### G02（P2）：全新 agent 的长任务恢复演练待完成

已覆盖工具级幂等、暂停、孤儿进程观察、历史原始文件缺失和批次输入漂移；尚需用真实宿主会话检验新 agent 是否能仅凭 TASK/STATE 恢复、消费生成的 RESULT、解释失败并继续优化。共享环境发布锁和 Markdown 摘要水位同步仍未工具化。

验收：全新上下文完成接续，未重投未知作业、未重复扣额；旧证据损坏能定位到具体产物，不影响无关任务收尾。

### G03（P2）：评测能力与隔离边界仍需按用途扩展

当前支持逐 case mean/median latency 上限；跨比较契约的 best 迁移和更复杂统计规则尚未提供。评测脚本与候选分别绑定、在独立子进程执行，但不提供恶意同账号代码的 OS 权限隔离。若需要接收不可信候选，应另行设计隔离后端，避免将本地合作开发模型当作安全沙箱。

### G04（P2）：发布生命周期未完成

源码安装支持清单、升级与回滚；npm 打包、卸载和旧运行包自动保存继续按 M3/M5 推进。开发软链接与受管副本安装已明确区分。
