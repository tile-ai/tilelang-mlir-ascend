# 与本次改动相关的正确性检视

实现或修复涉及索引、尾块、规约、共享缓冲、并行写入时读取。先沿输入到输出的数据流定位受影响代码，再选择下面的检查；不要求每次生成独立审查报告。将结论写入已有 PRECHECK/RESULT，记录源码位置、反例、依据和回归办法。

## 地址与任务覆盖

- 从逻辑元素推导 task/block/lane 的覆盖范围，检查没有漏算、重复写或跨任务错误归并。检查 grid 向上取整、最后一块和零长度是否符合契约。
- 展开实际地址表达式，包含 stride、广播、布局变换、workspace 偏移及地址单位。大 shape 的乘法与中间转换也要避免整数溢出，不能只看最终指针类型。
- 尾部 mask 必须覆盖所有可能越界的 load/store；先越界读取再 select 不能证明安全。规约填充值需符合运算，例如求和与最大值的中性值不同。
- 核对任务收到的实际 shape：包装层可能 padding 或裁剪。原始 case 名称含“尾块”不证明执行到了尾块路径。

可操作反例：tile 为 B，契约允许任意长度时检查 B−1、B、B+1 的最后几个有效元素；若只支持整除输入，应检查拒绝行为，不把非法输入作为正向通过要求。

## 数值与输出

检查输入转换、乘法与累加类型、规约顺序、舍入/截断、饱和和最终转换；中间结果范围可能大于输出范围。按任务的特殊值、空规约、相同值索引选择等语义检查 NaN/Inf、初值和 tie-breaking。

追踪每条分支的定义与使用：返回值、辅助索引/计数、workspace 和原地状态在读取前都已初始化。仅部分写入的 tile 不能把剩余垃圾值带入规约。多输出应分别核对；不能只验证主要张量而遗漏影响后续算子的 scale 或索引。

精度失败保存最差 case、具体坐标、输入邻域、期望值和实际值；区分系统性索引偏差、转换误差和偶发竞争。按冻结比较器判断，容限疑似错误交协调者修订契约。

## 所有权、同步与缓冲生命周期

对每个共享 buffer 写清“谁写、谁读、何时可读、何时可覆盖”。按生成代码核对生产/消费执行域与同步，而非仅以 DSL 中出现同步 API 作为证明。

多缓冲至少检查三个连续迭代及尾部排空：第 i 轮的数据在最后一个读者完成前，不能被第 i+k 轮覆盖。容量计算包括同时存活的所有 buffer、对齐、临时规约与流水版本，目标容量来自绑定环境。

跨任务写同一输出需有正确归并策略；原子写只解决其支持的局部操作，不保证多个字段的整体一致性或确定性。对原地/别名输入检查读后写依赖，参考与候选分别使用等价独立副本。依赖全局完成的算法不能靠块内同步代替跨核屏障。

编译器自动插入同步是实现依据的一部分；结合对应 revision 的 lowering/生成代码验证。增加同步后精度恢复，只是定位线索，仍需证明依赖与资源生命周期正确。

## 修复与范围

先修复最早能解释现象的错误，再固定新候选并回归全部必选精度及受影响性能项。直接修改 IR/生成代码只能作为诊断实验，最终改动回到可重建的 TileLang 源码。

verify-only/collect-only 没有源码修改范围时只记录修复需求；code-only 只执行已授权低成本检查。改变核心优化机制时提出新的 analysis/队列项建议，不在原 run 中扩展方向搜索。
