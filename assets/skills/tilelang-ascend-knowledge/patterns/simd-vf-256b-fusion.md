# 全 256B `SimdVF` 算子融合与消除 `SimtVF`

## 适用症状与触发条件

- `msprof` 显示 `aiv_vec` 占空比居高不下（如 0.7+），即使 Cube 已经高效流水，Vector 侧仍频繁拖慢 CV 交接。
- 生成代码中存在：① 多个相邻小向量阶段反复读写 UB；② 连续规则算术落入了 `SimtVF`；③ 在向量热循环内部出现 64-bit 整数除法或标量取模。

## 核心物理机理

1. **满宽 256B 向量化**：按 256B 向量宽度组织连续 UB 运算（如将两行较小宽度的向量合并打包处理），最大化每条向量指令的有效元素数，消除 `SimtVF` 的逐线程开销与寄存器压力。
2. **相邻向量阶段融合（如 `P` 与 `dS` 融合）**：把本应连续执行的 mask、缩放、exp、类型转换与后续 `dS` 运算融合到同一 `SimdVF` 中，减少中间 UB 落地与跨 VF 同步开销（实战中可将 Vector 占空比压降近半）。
3. **移出循环内 64-bit 除法**：用预先计算的乘加/移位或外提标量索引替代 VF 内部 64-bit 除法，避免在向量发射窗口插入高延迟标量指令。

## 适用与不适用边界

- **适用**：规则密集 UB 运算、元素级激活/mask/缩放、已知宽度归约、规则打包与反量化。
- **不适用**：高度不规则的稀疏 GM gather/scatter、依赖线程级原子操作或复杂数据相关分支的场景（此时将不规则部分隔离为独立小 `SimtVF` 或专用 DMA，不要强行用 SIMD 模拟）。

## 验证清单

- 检查生成 ASC：目标向量段已全部生成 `SimdVF`，无意外残留 `SimtVF` 或循环内 64-bit 整数除法。
- 对比 `msprof`：`aiv_vec` 占空比明显下降，且全精度/边界尾块（如 `D=32/64/96/160` 非满宽维度）通过 `NaN` 哨兵与全元素校验。
